1. **修打包脚本（P0）。** `apps/viewer-web/main.mjs` 一启动就导入 `plugins/mechanism-catalog.mjs`，它又导入 `plugins/atp-synthase/` 和 `plugins/kcsa/`，但 `desktop/scripts/package-platform.cjs` 第 36 行的复制列表只有 `plugins/rcsb` 和 `plugins/structure`。下次打包后新版 Viewer 很可能整个打不开。

### B. 结构与分析（放在结构插件或独立的分析插件里）

## 3. 每一项的验收标准

每迁完一项，都要满足下面全部条件，并按 [基线与结构工作流](BASELINE_AND_STRUCTURE_WORKFLOW.md) 的格式记录：

1. **数值和经典版一致**：列一张对照表（同一结构、同一种子、同一参数下的计数、比例、电流、步骤数等）。有差异就写原因，不能默默改掉。
2. **确定性**：同一种子重放结果相同；按固定步长单步走到某个时刻，与直接跳到该时刻的结果一致。
3. **保存后重开**：导出 v2 包再打开，结构、参数、进度、选择、镜头保持一致，不重新下载。
4. **插件停用**：停用插件后，场景仍显示静态结构，并给出看得懂的提示；资源全部释放。
5. **证据和命名**：所有非实验内容都标了证据等级；没有未命名的粒子。
6. **截图**：1440 和 560 宽各一张，放在 `docs/images/`，并且人工看过。
7. **测试**：新增 Node 测试；`tools/studio-smoke.cjs` 增加对应的冒烟测试；全部测试通过。

## 4. 工作规则

- **前端只做最低限度。** 新增的面板和控件沿用 `apps/viewer-web/viewer.css` 现有样式即可，不要做新画风、新主题或布局重排。需要经典版视觉才能看懂的地方（比如墨线），先保证数据和接口在，在报告里注明“需前端收尾”。
- **不要再多写一份实现。** 优先放进 `packages/` 和 `plugins/`，不要第三次实现解析、表示或场景会话。凡是 `src/` 和 `packages/` 都有实现的功能，在 `docs/DUPLICATION_MAP.md` 记一行，格式为 `功能 | 经典位置 | 新位置 | 是否等价`。Claude 收尾时按这张表合并。
- **插件接口有变化就写文档。** 插件宿主新增的注册点（播放器、面板、命令、表示等）写进 `packages/plugin-host/README.md`，并注明以后要放进沙箱时需要考虑的地方（插件直接访问了哪些 DOM / Three.js 对象）。
- **提交前**：`git fetch` 后再 `git pull --rebase --autostash`；`node tools/build.mjs --check` 通过；`node workshop/tools/validate.mjs` 全部通过；全部 Node 测试通过。
- **提交身份**：沿用仓库已有的作者设置；不要把任何个人邮箱写进仓库。
- **需要维护者做的事**（建账号、买证书、提供 API 密钥、在 ChimeraX / PyMOL 里手动核对）写进报告，不要跳过，也不要假装完成。
