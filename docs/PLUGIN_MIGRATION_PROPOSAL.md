# Claude Viewer 主体与插件迁移建议

> 目的：以 Claude 发布的经典 Viewer 为产品主体，把 Codex 新增的 Core、场景格式、Studio 和插件能力接入进来；在迁移中完整继承经典 Viewer 的前端能力、科学展示语义和既有场景。本文是实施与验收基线，不等于声称所有项目已完成。代码审计结论与风险等级见 [审计报告](AUDIT_REPORT_2026-11-18.md)。

## 版本基线与结论

- Claude 基线：`desktop-v0.3.2`，对应经典 Viewer v18.2（2026-11-16）。
- Codex 正式发行版：`desktop-v0.4.0`（2026-11-17）。
- 审计时 Codex 主分支：`202c0a9`（2026-11-18），包含四种呈现模式 M0–M2。
- 四模式文档的 M0 基线为 `9de64cd`；M1、M2 在其后继续增强导航和模式面板。

**核心判断：Claude 的经典 Viewer 并未从仓库删除。**它仍以 `src/` 为源码、由 `tools/build.mjs` 生成 `web/index.html`，也继续服务经典桌面工作区和 Skill。丢失发生在产品入口和架构整合层：Codex 的新版 `apps/viewer-web/` 是独立的轻量 Viewer，目前没有承载经典 Viewer 的大量分子前端交互；而已实现的插件宿主能力也不足以承载这些交互和模拟。因此，不能把新版 Viewer 目前已有的四模式面板等同于 Claude 原有能力已经迁入。

上述判断记录审计基线。后续按用户确定的新版主体＋插件方向，已交付结构工作流、经典表示、多结构兼容、ATP 合酶、KcsA、AdK 两态开合和基础命令接口。下表反映当前迁移进度；详细实测见 [验收记录](BASELINE_AND_STRUCTURE_WORKFLOW.md)。

建议目标是**经典 Viewer 的前端体验作为主体，Codex 平台作为底层和扩展机制**。不应先把经典 UI 改造成新版几何编辑器的样子，再逐项补回功能。先冻结 Claude 前端行为基线，再为可插拔功能定义接口，并按模块迁移、逐项验收。

## 当前两套前端分别提供什么

| 能力 | Claude 经典 Viewer（`src/` → `web/`） | Codex 新 Viewer（`apps/viewer-web/`） |

| 分子数据 | RCSB、PDB/mmCIF、本地结构、CCD 配体、链/残基/注释 | 可选官方结构插件；导入 PDB/mmCIF 或 RCSB，生成通用几何预览及原始文件资产 |
| 结构表现 | 团块、二级结构 cartoon、按功能简化、插画、键级小分子等 | 官方结构插件提供 backbone、cartoon、墨线团块、密度表面和功能分区，可按部件切换 |
| 讲解交互 | 残基/部件点选、标签、证据、结合位点、界面、能量步骤 | 节点点选、层级导航、热点、视角书签、注释/证据列表、示意连接 |

| 四层视图 | 细胞 → 局部系统 → 蛋白质，并从系统/蛋白质进入机制 | `cell/system/protein/mechanism` 导航及 Studio M3 作者流程已实现；ATP 与 KcsA 复用系统/蛋白质/机理导航，细胞领域内容待迁移 |
| 桌面工作区 | 经典 Viewer、开发者工作台、创意工坊工作流 | 默认新 Viewer；可切换 Studio、经典 Viewer、开发者工作台 |

## 前端必须继承的体验契约

### 视口与视觉

1. 保留 Claude 的白底科学插画语言：结构边缘墨线、柔和体积明暗、远处淡入纸色、膜脂降低视觉权重。新版通用网格/默认灰色几何不能成为默认分子外观。
2. 结构、配体、粒子、标签、膜、口袋/界面表面均需有明确图层与显示顺序；选择/高亮不能遮挡核心结构；镜头转动、缩放、剖切时标签与裁切稳定。
3. 降低显卡能力时保留信息层级和可读性，逐级降低高开销表现；不能因为 WebGL 高级效果不可用而打不开场景。
4. 镜头聚焦、重置、书签、视图导航共用一个相机状态接口。过渡可取消，支持减少动态效果；切换视图后按响应式画布重新取景。

### 结构交互

1. 点残基必须能得到作者残基编号、链、残基名和化学信息；点配体进入配体聚焦而非只选中一个普通几何节点。
2. 选择必须能带动信息卡、序列条、接触残基、证据条、镜头及动画当前步骤同步；取消/返回时恢复之前选择和镜头。
3. 链/部件树支持逐项显隐、聚焦和拆装；隐藏节点不能参与拾取、标签、覆盖层或接触高亮。
4. 选择语言和开发者 API 继续可用，方便老师、研究者、AI 工作台与嵌入网页调用相同动作。

### 教学/科学面板

1. 原有的能量转化条、过程控制、时间尺度、实验开关、抗生素/阻断剂、pH/浓度/电位调节分别由能力贡献 UI，但沿用宿主统一的面板区域、键盘焦点和可访问性规则。
2. 四模式导航表达同一个真实场景树：细胞、局部系统、蛋白质、机制步骤。它要能从旧预设和 `.glow` v1 自动生成入口；不可要求用户为同一内容再手写一份仅供新版 Viewer 使用的伪造节点树。
3. 实验、推算、建模、示意的来源提示贯穿结构、轨迹、参数和动画；播放中可查看当前步骤的参与对象和证据解释。

## Codex 插件底座的缺口

当前 `packages/plugin-host/index.mjs` 支持的注册点只有 `importers`、`representations` 和 `services`。结构插件 `plugins/structure/` 当前解析坐标、生成基础 cartoon 预览并提供结构查询服务。该接口还没有涵盖 Claude 的前端和机制运行时。以下扩展是迁移必要项：

1. **表示和视口契约**：插件能提供分子专用表示层、材质/调色板、拾取语义、图例、选择覆盖、剖切/标签/膜层，并能在主体中按场景切换和释放。
2. **场景能力声明**：声明场景可提供哪些表示、选择器、分析器、过程播放器、证据/注释、面板控件和四模式入口。包里记录精确能力 ID/版本与必需/可选关系。
3. **仿真/过程接口**：插件注册播放器，消费确定性时钟、seed、暂停/单步/倍速/时间尺度、时间线采样和生命周期信号；可产生结构 pose、粒子、字幕、能量/浓度读数和参与对象高亮。
4. **宿主 UI 扩展**：插件只能向已定义插槽贡献受控的面板、动作、图例和参数表单，不能自行替换整个应用页面。加载/卸载要清理 DOM 事件、Worker、GPU 资源、动画帧和异步请求。
5. **结构语义与选取**：提供结构模型、作者/标签编号映射、链/残基/原子/配体/部件 ID、CCD 键级和来源；当前预览的 `chainId` 扩展不足以表达原 Viewer 的精细操作。
6. **旧接口兼容**：以 adapter 保留 `window.glow` 和 `postMessage` 协议，将 `process`、`reps`、`scene.structure`、`.glow` v1 映射到新能力；兼容命令须继续通过来源 allow-list、用户同意和取消语义。
7. **离线/缺插件行为**：能显示包内通用几何和标注；缺过程插件时给出明确能力提示与安装/启用方式，不静默删掉机制、证据、结构部件或场景数据。
8. **可信插件边界**：继续保持插件来自宿主显式提供的受信模块，场景包只含数据。第三方插件隔离/分发不能借由 `.glow` 包代码执行绕过。

## 实施顺序

### P0：锁定 Claude 主体并打通一条端到端链

- 将 `src/` 的经典 Viewer UI 和分子视口作为主界面基线；现有 `window.glow` 命令、键盘交互、开场方式、显示模式和相机动作先做截图/行为基线。
- 从 Core 加载、保存、取消加载、时间线、资源释放中选择可复用服务，以 façade 包装现有状态；不要一次性把全部经典业务状态重写成通用节点。
- 扩充插件 API 到表示、选择语义、UI 插槽、播放器/过程、分析服务和证据贡献。先做官方结构插件，使一个真实 PDB 可加载、逐残基选取、切表示、聚焦配体、显示证据。
- 接入四模式导航，但以旧场景/预设为数据源；来回导航保留镜头、选中对象、动画和面板状态。
- 挑一个最能暴露能力边界的机制做端到端示范（推荐 ATP 合酶或 KcsA）：真实结构、原有视觉、粒子/字幕、时间线/步骤高亮、参数控件、旧版场景兼容和插件缺失提示均可用。

### P1：迁移主要机制与复合系统

- 分别注册 ATP 合酶、KcsA、腺苷酸激酶、鞭毛马达、呼吸链、光反应和翻译能力；按机制复杂度拆插件，不把所有逻辑塞进结构插件。
- 恢复配体/口袋/相互作用/域运动分析、拆装亚基、细胞区室仪表盘、seed 与模拟参数控制。
- 将剩余旧预设与 `.glow` 官方包纳入导入、自动生成四模式入口和兼容性回归。

### P2：Studio 作者工作流和生态

- Studio 能创建/修改上述领域场景字段、调用可用插件提供的作者工具，并导出能由主体 Viewer 完整播放的包。
- 明确插件安装/版本诊断与场景需求展示。完善 Windows、Web、离线缓存和受信第三方插件策略。

## 完成验收标准

- **前端无回退**：在 560 px 窄窗口及桌面宽屏复验 Claude 基线的工具可达、图层层次、镜头、标签、配体焦点、面板/弹窗、减少动效；对比基线截图和关键交互。
- **真实结构**：用 Claude 的既有结构预设、至少一个任意 RCSB 条目、PDB/mmCIF 本地文件验证原子/残基编号、链、配体、二级结构、来源与失败提示。
- **真实机制**：对迁移的每个过程验证开始/暂停/继续/单步/拖时间线/倍速/seed 可复现，当前步骤和参与结构同步高亮，参数改变能反映在模拟输出。
- **兼容包**：15 个 Claude 官方 `.glow` v1 包逐个打开；要求保留结构、证据、字幕、注释和可表示数据。过程暂未迁移时必须显式说明，不得静默变成普通静态物体。
- **接口兼容**：旧 `window.glow` 命令示例和嵌入消息回包可执行，来源检查与用户同意仍有效；命令历史可重放。
- **生命周期**：快速切场景/禁用插件/关闭视图时，不遗留旧场景 GPU 几何、Worker、请求或监听器；插件版本不匹配时保留数据并给出可读诊断。
- **Studio 到 Viewer**：Studio 导出的领域场景在主体 Viewer 中打开后与其编辑预览一致；保存再打开保持结构、导航、时间线和证据。
