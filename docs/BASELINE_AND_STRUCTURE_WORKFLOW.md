# 基线与结构工作流实施清单

本文落实整体计划的第 1、2 项：冻结经典 Viewer 的产品行为基线，并定义新版主体的真实结构端到端工作流。它是实施清单，不表示下列尚未验证的交互已经在新版 Viewer 完成。

## 1. 产品基线

### 代码入口

- 经典 Viewer 源码：`src/`；构建产物：`web/index.html`；构建命令：`node tools/build.mjs`。
- 新 Viewer：`apps/viewer-web/`；结构解析与表示原型：`plugins/structure/`；RCSB 插件：`plugins/rcsb/`。
- 经典体验范围包括结构载入、三种蛋白表示与插画风格、配体聚焦、残基/部件交互、证据与字幕、场景/机制控制，以及 `window.glow` API。

### 行为基线清单

| 区域 | 需要记录的基线行为 | 新主体继承要求 |
|---|---|---|
| 启动与载入 | 预设、PDB 编号、本地 PDB/mmCIF、加载错误与取消 | 同一入口可调用结构能力；失败可恢复且不留下半载入场景 |
| 视口 | 默认白底插画、旋转/缩放、重置、聚焦与过渡取消 | 镜头状态统一；切换导航后能恢复原视角 |
| 表示 | 团块、结构示意、简化示意、部件可见性 | 表示可切换，配色、图层和低性能降级保留语义 |
| 选择 | 残基/部件/配体点选、背景淡化、信息卡、Esc 取消 | 选择事件保留结构 ID、链、auth/label 编号、插入码与配体 ID |
| 教学信息 | 图例、标签、证据、字幕、步骤与能量条 | 导航/时间线操作不清除这些状态 |
| API 与嵌入 | `window.glow` 命令、命令日志、嵌入消息 | 维持命令语义和来源校验，统一转发到新场景状态 |
| 窗口适配 | 桌面宽屏与 560 px 窄窗口的控件可达性 | 两种尺寸下关键功能可操作，布局和镜头稳定 |

### 2026-11-18 实测记录

以提交 `becad54` 的经典 Web Viewer 为基线。使用 Electron 33.4.11、SwiftShader 和中等画质。测试输入 `4HHB-cache.cif` 由 RCSB ModelServer 的缓存坐标组装，使用 `4hhb/atoms` 的 `label_atom_id=CA` 和 `label_entity_id=3` 两份 CIF 响应，将坐标行合并到同一 `_atom_site` 循环。文件 SHA-256 为 `1e7bc8a686c68036e3ef2086c1807862a21990bc32217b7770bf423fc054bc94`。这个样例只有蛋白 Cα 和 HEM 坐标。

| 操作 | 观察结果 |
|---|---|
| 默认启动 | PDB 输入框显示 `6ZPO`，尝试加载 ATP 合酶。离线测试返回 HTTP 503，状态栏显示载入失败；联网启动和动画待验收 |
| 在视口拖入样例 mmCIF | 显示白底插画、轮廓与配体球棍。A/B/C/D 链分别为 141/146/141/146 个残基，共 574 个；1 种配体，共 4 个 HEM |
| 宽屏与窄屏 | [1440 × 900](images/classic-4hhb-1440.png) 左侧工具栏与分子并排。[560 × 900](images/classic-4hhb-560.png) 底部滚动面板保留载入、预设与场景包入口，其展开状态遮住部分模型，模型两侧也有裁切 |
| 调用 `glow.select('chain A and resi 58')`，再向页面派发 Esc 键盘事件 | 匹配并选中 1 个残基，Esc 后视口选中计数回到 0 |
| 调用 `glow.camera({focus:'chain A and resi 58'})` | 镜头距离从 1.2 变为 0.269 |
| 切换“团块（写实）”和“结构示意（螺旋 / 折叠）” | 触发两个模式对应的控件事件后，`glow.info()` 分别返回 `blob` 和 `cartoon`；示意模式的视觉对比与部件简化待验收 |
| 点击 HEM 行的聚焦按钮 | 本地导入的配体没有可下载结合位点的来源条目，界面明确提示。带 RCSB 来源的结合位点和接触信息待联网验收 |

本轮还待记录本地 PDB、鼠标拾取、四模式返回、命令嵌入、窗口内完整键盘操作和机制播放。通过联网数据补齐 ATP 合酶默认开场及真实配体结合位点的截图后，再用同一操作表与新版 Viewer 比对。

## 2. 真实结构端到端工作流

### 用户路径

1. 用户从 RCSB 输入 PDB 编号，或拖入本地 PDB/mmCIF 文件。
2. 导入器保留原始字节、来源、文件名/编号和格式；解析结构模型并提供链、残基、原子、配体与来源元数据。
3. 主体调用结构表示能力生成初始视图；用户可切换表示、点选残基或配体。
4. 选择驱动信息卡和镜头聚焦；配体选择进入结合位点视图，并提供接触信息入口。
5. 用户保存场景为 Glow 包，关闭后重新打开；结构、来源、视图、表示和选择相关持久化状态按格式约定恢复。

### 数据与交互契约

- 结构实例有稳定 ID；链、残基和配体对象使用稳定对象 ID，并保留 author 与 label 编号映射及插入码。
- 解析结果与原始资产分离保存，记录来源 URI/编号、格式、哈希和解析器版本；网络资源需支持取消与缓存策略。
- 表示能力接收结构模型、视口和场景配置，返回可释放的渲染层及拾取映射；结构插件卸载或场景替换时释放 GPU 资源与监听器。
- 拾取结果通过统一选择事件送达信息面板、相机和后续分析服务，不由渲染器直接改写多个 UI 状态。
- 外部 PDB 下载失败、格式错误、空结构和不支持字段都显示可理解的错误；保留原文件/场景数据，不生成误导性的空白成功状态。

### 分阶段交付

| 交付 | 完成条件 |
|---|---|
| A. 导入闭环 | RCSB 编号与本地 PDB/mmCIF 均可导入；原始数据、来源、链/残基映射可查询 |
| B. 显示闭环 | 初始结构可显示；基础表示切换可用；模型重载和取消不残留旧图层 |
| C. 选择闭环 | 点选真实残基/配体返回正确身份；信息卡及镜头响应；Esc 清除选择 |
| D. 持久化闭环 | 保存并重开后结构与来源一致；包内资产和外部 accession 两条路径均有定义 |
| E. 兼容闭环 | 经典预设行为作为对照；缺失插件或网络时显示明确诊断，不静默丢失场景信息 |

## 验收记录模板

每个验收样例记录：结构来源与编号/文件哈希、链与目标残基/配体、导入结果、表示、选择结果、镜头行为、保存重开结果、错误/降级提示、浏览器或桌面版本、截图位置。至少覆盖一个 RCSB 条目和一个本地 mmCIF；PDB 本地文件可作为补充格式样例。

## 新版 Viewer 实测

Electron 33.4.11 测试覆盖了真实 RCSB 4HHB 导入、本地合成 PDB/mmCIF 导入、点击 HIS（作者 A:8B，标签 X:2）和 HEM（作者 A:101）、Esc、表示切换、最近重原子距离，以及坏文件和快速切换时保留有效场景。保存重开验证了字节、SHA-256、来源、表示和选择，镜头随场景保存。停用插件后重开仍可显示包内预览。检查了 4HHB 墨线团块的 [1440 px 宽屏](images/viewer-4hhb-blob-normal.png) 和 [560 px 窄屏](images/viewer-4hhb-blob-narrow.png)。

设置 `GLOW_STRUCTURE_SCREENSHOTS` 为输出目录，用 Electron 运行 `tools/studio-smoke.cjs` 可复验。另设 `GLOW_LIVE_STRUCTURE_SMOKE=1` 切换到真实 RCSB 下载，并逐个检查官方包，输出 `official-v1-report.json`。

| v1 官方包 | 新版 Viewer 联网结果 |
|---|---|
| adenylate-kinase、adk-reaction-data、atp-synthase、groel、kcsa-data、kcsa、nucleosome、proteasome-20s、respiratory-chain、spike | 显示第一个 RCSB 条目的结构预览 |
| cell-corner、flagellar-motor、translation、whole-cell | 完整坐标超过 30 MiB，显示来自 ModelServer 的 Cα/P 预览 |
| chloroplast-light | 显示主结构，按场景的资源上限省略部分预览分组，保留下载的原始坐标 |

带字幕、部件讲解或旧证据字段的包可以在「标注、证据与视角」查看相应内容。

多结构复验覆盖 5 个声明 `components` 的官方包，共 13 个附加组件条目。叶绿体光反应加载了 6 个组件，鞭毛马达恢复了 11 个定子副本和 130 个鞭毛丝副本。呼吸链和叶绿体使用正对复合体排列方向的初始镜头。针对找不到相应名称、由过程决定位置或超出容量的组件，查看器会给出诊断。

本地 Electron 用合成 v1 场景复验了三个环形副本、指定配色、隐藏部件与简化主链。保存为 v2 后关闭重开，组件节点和变换保持一致；切换「部件显隐」并再次保存后，包内节点可见性随之更新。

生物组装体验收覆盖 mmCIF 操作列表与组合、PDB `REMARK 350`、缺少组装说明时的原始坐标回退、原文件字节保持以及 v2 重开。真实 [1K4C 组装体 1](images/viewer-1k4c-assembly.png) 展开得到 18,136 个原子与 12 条聚合物链。15 个官方旧包复验均显示了主结构及全部声明的附加组件。

在 [4HHB 的 560 px 截图](images/viewer-4hhb-functional.png) 核对了功能分区。当前模式将配体重原子 8 Å 内的 Cα/P 代表点及 v1 主结构指定的核心画成橙色。其余体积基于坐标分组估算。保存重开会恢复该模式及示意证据。原版低分辨率分区形状、部件表面和机制播放仍待迁移。

在实际 6ZPO 组装体 1 上，按旧 ATP 合酶预设的残基范围和指定邻域规则生成了 416 个核心代表点。只计算配体邻域时为 326 个。
