# 代码结构、当前现状与后续拆分方案

核对日期：2026-11-19；代码基线：759102f。本文描述当前代码及目标边界，执行编号只在 [ROADMAP](ROADMAP.md) 维护。历史版本见 [修订前快照](history/2026-11-19-before-authoring-priority/README.md)，历史决策综合见 [沿革总结](history/EVOLUTION_SUMMARY.md)。本次仅整理文档与执行契约，没有完成新的功能迁移。

## 1. 产品目标与优先级

**先实现软件制作基底，再将 Claude 历史版已有功能按功能拆成专用插件，最后扩展新增科研插件。** 专用插件包括分子表示、构象运动、粒子/流、反应/区室、序列过程、拆装、教学讲解等，不限于科研分析；“专用”指领域工具，不指给某个蛋白或作品单写一个播放器。

| 对象 | 职责 | 示例 |
|---|---|---|
| 主体/制作基底 | 文档与资源状态、对象/选择、编辑操作、时间轴、播放、工程保存、能力宿主与工具接线 | Viewer、Studio、Core、Schema |
| 功能插件 | 针对明确输入提供可复用制作/模拟/分析功能；输出数据与状态 | 构象插值、轴旋转、粒子路径、反应网络、测量 |
| 资源 | 可复用原始材料及来源，不含作品剧情 | 蛋白质 PDB/mmCIF、复合体、配体、实验构象 |
| 作品 | 资源实例＋工具配置＋动画/模拟规则＋讲解/结果 | 线粒体呼吸链、ATP 教学、KcsA 实验、全细胞展示 |

工坊划分**资源区、作品区**；功能插件由宿主管理，不能以工坊作品中的脚本安装。作者流程：导入/选择资源 → 放入工程成为实例 → 选用功能工具 → 配置并预览 → 保存可编辑工程 → 导出/分享作品。新作品应复用已有工具；有真实算法缺口才扩充功能插件。

## 4. 制作基底先补什么

| 基底能力 | 复用位置 | 需补齐的契约/流程 |
|---|---|---|
| 资源身份与复用 | Schema assets、结构/RCSB 导入、资源 Map | 资源 ID/版本/哈希/来源/署名授权，原始数据与实例分离，多工程引用与离线副本策略 |
| 可编辑工程 | studio-editor、Core store | 导入结构到场景树，创建多个实例，配置工具，撤销/重做，工程与作品往返不丢领域数据 |
| 工具挂载 | plugin-host、Studio/Viewer 面板 | 声明输入/适用条件、参数/单位/验证、输出、依赖、生命周期；工具在作者界面可操作且有命令入口 |
| 动画与运行状态 | timeline、现有 player 适配 | 区分动画轨道、模拟状态和渲染缓存；统一播放/暂停/步进/seek、种子/时钟与状态保存规则 |
| 输出与重开 | archive、project-io、scene-io | 工程可继续编辑、作品可播放；保存资源确切字节/依赖版本、参数历史、时间、镜头与证据 |
| 工坊最小路径 | 现有目录、校验、投稿 | 资源/作品分类和引用先贯通，再完善发布/检索；不等待最终视觉设计才验证功能 |

仅建立文档或重命名目录不算基底完成。至少验证“导入蛋白→保存资源→在作品创建实例→配置工具→预览→保存重开”，再用第二个结构/作品复用同一工具。

以下是**候选能力边界，均为待拆分/迁移**；不表示同名目录已存在，也不要求每个表格行都必须成为独立包。独立发布/依赖/生命周期确有需要才拆物理包，共享算法保留单一来源。

| 功能组 | 当前经典来源 / 新版复用点 | 提取出的能力 | 留在资源/作品中的内容 |
|---|---|---|---|
| 导入与结构表示 | `src/data/`、`src/repr/`；structure/rcsb | 解析/组装体、团块/cartoon/简化/插画、配体球棍/键级、剖切与着色 | accession、链选择、材料/配色配置、构图 |
| 选择与结构操作 | `src/derived/selection*.js`、`src/ui/take-apart.js`、`src/api/` | 完整选择集/表达式、序列映射、拆装、实例/子单元操作 | 被选对象、拆装步骤、镜头和说明 |
| 构象与对象运动 | `src/derived/geometry.js`、`src/sim/anim-runner.js`；alignment、AdK/ATP | 拟合/对应、构象插值、轴旋转、路径/联动及时间控制 | 两端构象、域/轴/锚点、速率、动作编排 |
| 粒子与流 | `src/sim/motion-kit.js`、各过程粒子代码 | 粒子池、命名、布朗/路径、避障、定向流、显示缩放 | 物种、粒子名称、路径端点、颜色、浓度/数量 |
| 数据反应与区室 | `src/sim/data-anim.js`、`cell-kinetics.js` | compartments/species/pools/flows/reactions、计量、事件、浓度/pH/电位与守恒 | 反应式/网络、区室几何、初始量、边界条件、参数单位 |
| 门控与随机过程 | KcsA kinetics、`src/sim/processes/kcsa.js` | 可配置门控状态、动力学/阻断输入、通量、可复验 RNG/时钟 | 通道结构、速率模型选择及参数、离子/阻断剂配置 |

| 环境与多站组合 | membrane、crowding、cell-corner、whole-cell | 膜/拥挤环境、区室可视化、多过程隔离、跨尺度实例导航 | 细胞布局、尺度层级、成员资源与过程组合 |
| 讲解与观测 | evidence、labels、energy-strip、controls | 字幕/步骤、证据、命名标签、计数/曲线/能量条、镜头书签 | 教学剧情、引用、图例、特定曲线和能量步骤配置 |
| 历史已有结构分析 | pocket、tunnel、ligand-focus、measure、sequence-bar | 经典测量/接触/口袋/界面、域测量、定膜和功能位点等 | 被分析资源/选择、参数、结果和解释 |

**历史已有的分析能力属于经典功能恢复，不被移到最后等待。** 后置的是新增科研方法、外部研究数据库/专业软件集成以及新的专业判断工具；其内容待经典能力与制作闭环通过后另行定义，当前不承诺某个新科研算法已经存在。

### 现有三个专用实现怎样拆

| 现有实现 | 先保留的能力/证据 | 拆分方向 |
|---|---|---|
| ATP 合酶 | 转子/β 构象、粒子、计数、保存/确定性及现有科学卡 | 旋转/构象/粒子/计量能力进入功能工具；6ZPO、链分组/轴、膜布局、8 H⁺/3 ATP 参数与剧情进入资源和作品；保留模型适用条件与计数语义差异 |
| KcsA | 五结构准备、门控速率、阻断/通量及科学卡 | 通用准备/构象与门控、区室/粒子/曲线能力分离；具体通道结构、E71A/WT 说明、模型参数和离子条件进入作品；专门数学模型可作为有适用范围的算法策略，不能退化成只按蛋白名分发作品 |
| AdK | CORE 叠合、两态插值、域测量及科学卡 | 提取对应/拟合/插值/域测量；4AKE/1AKE、CORE/NMP/LID 选择、Ap5A 和剧情归资源/作品；反应示例由数据反应工具承担，两态开合不冒称催化动力学 |

不是删掉领域科学模型并用普通关键帧替代。无法纯数据表达的有效算法继续以受信功能代码实现；作品仅选择并配置该能力，不携带脚本。

## 6. 拆分方法与兼容门槛

1. 为每项能力登记经典来源、现有新版实现、目标输入/输出、内容字段、状态所有权、依赖和已有测试，维护 [重复实现表](DUPLICATION_MAP.md)。
2. 先补稳定接口和适配层，沿用 Core/Schema/编辑会话；模型准备、运行与渲染输出分开，不能复制第三套解析/科学模型。
3. 把结构编号、布局、选区、参数、镜头/讲解抽为资源与作品数据；能力暴露可配置工具，默认示例可保留。
4. 兼容旧 process/player ID，转换到能力与作品配置；不能因为新 ID 导致旧包静默变成静态预览。缺能力说明准确，原文件保留。
5. 对照同结构/参数、单位、计量、RNG/时钟、事件、构象、保存重开、取消/释放；差异保持待验收。再验证第二个适用输入复用，证明工具不只服务一个预设。
6. 逐项切换目录与调用方，删除已被替代的新版重复代码；经典保留到足够证据且获明确迁移决策，最终全面前端/视觉收尾沿用交接。

资源来源卡、插件方法/假设卡、作品条件/解释分层保存；现有科学卡先保留映射，不能因搬字段丢掉物种、突变体、单位或模型限制。

## 7. 状态与安全边界

原始资源字节不可被实例变换或分析覆盖；作品引用确切资源版本/哈希，既可引用也可按授权带离线副本。场景坐标单位沿用 Schema 的米；原始分子坐标和测量的 Å 换算必须显式，模拟时间与演示时间不可混用。导入任意结构不会自动得到正确生物机制。

工具只通过宿主/编辑命令提交可持久化数据；模拟私有运行状态要可序列化、可释放，GPU 网格不是第二份业务事实源。分析结果保存方法/版本/参数、资源哈希、单位、误差/限制，不篡改原结构。网络、外部程序与敏感读取沿用权限控制。

工坊数据不执行 JavaScript；精确插件版本/能力缺失时给出诊断。当前宿主只是受信模块管理，不能宣传已完成任意第三方插件隔离；完整沙箱单独验收。

## 8. 本轮与后续交付界限

本轮只交付当前结构/现状、历史总结、功能拆分矩阵与修订计划。旧叙述归 history，routine 不动；machine parity 和科学证据保持可追溯。后续按 [ROADMAP](ROADMAP.md) 实现制作基底、经典功能插件、作者/工坊闭环，随后做新增科研插件。任何文档中的“目标/候选/待做”都不是现有功能声明。
