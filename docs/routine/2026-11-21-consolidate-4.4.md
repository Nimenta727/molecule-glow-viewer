# 2026-11-21 · 4.4 巩固：鞭毛换向、细胞一角布局、重复加载稳定性、能量条/pH 体积肉眼确认

## 做了什么

1. **鞭毛马达的换向与驱动梯度**（`plugins/simulation/works/mechanism-kinetics.mjs` 的 `FLAGELLAR_KINETICS`）：经典只在文字里说“CheY-P 可让转向切换”，没有开关也没有梯度控件。现在作品带两个控件：**质子动力势**（0–200 mV，默认 150，转速线性）和 **CheY-P 结合（顺时针）**（开关）。反转后每转仍是 44 个质子（质子跟着转过的圈数走，不分方向）；梯度为 0 时马达不转、不过质子。默认值下角度与计数与原来逐位相同；中途换向写进干预日志，回退重放得到同一角度。
   - 顺带修了引擎里的一个小问题：相位为 0 的第一个定子在转子完全没动时也会放过一个质子（`travelled >= phase`），现在要求转子真的动过（`travelled > 0`）。动起来之后的计数不变。
2. **细胞一角布局**（`plugins/simulation/corner-layout.mjs`，`tools/corner-parity.mjs`，报告 `docs/parity/corner-parity-report.txt`）：膜在核糖体顶部上方 60 Å，通道质心移到核糖体切面里、核糖体半径 0.3 倍处偏左，拥挤盒在膜下 34 Å。在真实 4V6F 与 1K4C 上，经典 `cell-corner.js` 的原句（vm 里原样运行）与纯函数 8/8 一致，包括经典 `Rr`（翻译设置里的原句）。**Viewer 还没把这个位移应用到通道节点**（仍用通用旧布局规则放置）。
3. **重复加载稳定性**：视口新增只读的 `stats()`（GPU 几何、纹理、着色器程序、场景对象数），页面暴露 `window.__glowStats()`；`tools/viewer-stability-check.cjs` 在真实 Chromium 里把 1K4C、6ZPO、4AKE 各载入 6 轮（含表示切换），结果：几何/纹理/程序/对象数每轮不变（21g/115g/9g；4t；4p），JS 堆（强制回收后）每轮增长约 0.1–0.3 MB 并趋平，在容差内。
4. **能量条、pH 体积肉眼确认**：`tools/work-shot.cjs`（真实 Chromium，请求拦截提供仓库与固定结构）打开呼吸链作品：顶部七步能量条、第一步点亮；结构周围半透明 pH 体积盒；动画面板计数随模型（2.9 秒动画时间内泵出 4 个 H⁺）。软件渲染每秒约一帧，所以只看到周期的开头。
5. **打开作品时的提示整理**：我的缺失能力报告只把“警告”和旧工具编号写进诊断（可选的旧过程插件不再提示）；迁移时那句“当前迁移不会运行旧版过程”在已有工具条目覆盖它时不再显示（它已经不是事实）。
