# 2026-11-21 · 4.5.2 作者全流程：发布检查、版本升级、派生、场景包入库、草稿恢复、缺失能力

## 做了什么

1. **场景的 `publication` 块**（`packages/schema/documents.mjs`，可选，v2/v3 都能带）：授权、作者（https 链接）、版本、更新日期、主题、简介、标签、`derivedFrom`。Studio 新增可撤销的 `setPublication` 命令。
2. **发布检查** `plugins/workshop/publish.mjs`（纯函数）：编号合法/保留、标题、授权认可、主题、同编号作品的版本升级（须同作者、版本更大、不能放宽 CC BY-SA）、派生来源（存在、版本不超、授权兼容、无环）、工具是否可用、资源是否允许嵌入、CC BY-SA 资源强制作品授权。另有 `nextRevision`（下一版的发布信息）和 `deriveFrom`（从某作品派生，授权默认取最宽松且被允许的）。
3. **工坊收场景包**：`workshop/tools/glow-lib.mjs` 新增 `checkPackageFile`（读 v2/v3 ZIP，跑同一发布检查；已发布的相同文件不算“升级”所以重复校验不会误报）；`validate.mjs`/`build-index.mjs` 同时处理经典 v1 与场景包；索引由 `publication` 生成。`GLOW_WORKSHOP_DIR` 可指向工坊目录的副本（测试用）。端到端测试：发布 → 索引 → 目录客户端能搜到 → 同版本改内容被拒 → 升版通过 → 派生授权对错。
4. **Studio“发布”标签**：表单模型 `apps/studio-web/publish-form.mjs`（纯函数，带校验与授权收窄）；读取工坊目录后给出已有版本提示、派生下拉；发布检查结果分“问题/注意/说明”。
5. **草稿恢复** `packages/studio-editor/recovery.mjs`：编辑 3 秒后把工程写进 IndexedDB（保留最新 3 份，带 SHA-256，损坏的跳过，存储失败只报告不抛错）；下次打开 Studio 顶部提示“恢复草稿 / 丢弃”；“保存项目”后清除。
6. **缺失能力与旧编号** `apps/viewer-web/capabilities.mjs`：打开场景时报告缺失工具（该部分不运行，其余照常）、旧工具编号（按现行编号运行）、缺失/版本不同的插件；写进场景诊断，不再让场景打不开。
7. 文档：Skill 的 `platform.md` 增加“从制作到发布”六步；`workshop/SCHEMA.md` 的 `derivedFrom`；`docs/STATUS.md`、`docs/ROADMAP.md`。
