# 2026-11-20 — 4.4.3a 数据动画引擎（纯逻辑）

## 做了什么
- **新目录 `plugins/simulation/`**（目标包之一），提取经典 `src/sim/data-anim.js`：
  - `data-spec.mjs`：读取“数据动画 v1”声明（物种、区室、池、流、反应、锚点）。只保留已知字段、数值夹范围、数量设上限，**检查每一处引用**——经典在池/流/反应写了不存在的区室时运行中直接崩，这里读取时就拒绝并说明哪一处错了。包里没有任何代码。
  - `data-animation.mjs`：`DataAnimation` 引擎。区室（盒/外壳、上下侧、膜、间隙）、池、流（取分子 → 布朗路径入口 → 经锚点 → 出口 → 放入另一区室，事件与计数器）、反应（反应物到位点 → 保持 → 消耗 → 事件 → 计数 → 产物扩散或淡出）、快时间尺度的粒子流。一步的顺序是经典一帧的顺序（启动流/反应 → 行进推进 → 池移动 → 续接），所以同一种子取随机数的顺序也一致。
  - `plugins/motion` 的 `Motion` 增加**延后续接**（对应经典里 Promise 续接在整帧同步工作之后才跑）和**定时器**；`ParticlePool` 增加边界漂入/漂出计数。默认行为不变，原有对照 24/24 仍一致。
- **新增（超出经典）**：计量台账（每个物种创建/消耗/消失/取出/归还）+ `balance()`；`conserved` 声明的守恒量在每个反应完成时检查（不守恒就记入 `violations` 并出带 ⚠ 的事件）。

## 怎么验证的
- **与经典对照**（`tools/data-anim-parity.mjs`，报告 `docs/parity/data-anim-parity-report.txt`）：原样运行经典 `data-anim.js` + `motion-kit.js` + `anim-runner.js`，同一种子、同一结构（4AKE、1K4C、6ZPO 的真实残基位置，把包里写的 K/AP5 小分子和膜放在上面），按经典帧循环的方式逐步比较：池里的分子（位置/模式/透明度）、在路上的分子、计数器、事件日志、快尺度粒子流。AdK 反应包 900 步、KcsA 数据包 1200 步（两个结构）、两个包的快尺度各 500 步、一个无来源/无去向的流 500 步：位置差 ≤ 7e-14 Å，**6/6 一致**。
- 单元测试 9 项：官方两个包读取无错误；读取器拒绝/夹范围/设上限；锚点解析；AdK 反应（池、反应、事件、计数、计量平衡）；KcsA 流（K⁺ 外流、事件在点上触发、计数、计量平衡）；同种子同历史、快尺度计数与命名的流；守恒量通过与不守恒报告；无来源/去向的流；dispose 后不再有任何动作。全套测试通过。
