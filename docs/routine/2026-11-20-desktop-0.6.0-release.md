# 2026-11-20 · Desktop 0.6.0 发布与打包闸门修复

## 做了什么

1. **修复 Windows 打包失败**：`platform-release-gate` 的 windows-artifact 作业自 4.4.2d 起一直在“Build and check stage dependency closure”步骤失败。原因是 `tools/check-platform-stage.cjs` 要求 `plugins/mechanism-catalog.mjs` 引入的每个插件都带 `scientific-card.json`，而 `motion`、`simulation` 是纯工具框架插件，没有也不该有科学卡。
   - 新规则：插件 `index.mjs` 注册了播放器（`registerPlayer`）才算机理插件、必须带卡。
   - `tools/test/packaging.test.cjs` 新增用例：纯工具插件无卡通过；注册播放器的插件缺卡仍报错。
   - 本地验证：暂存检查通过（177 个模块，ATP/KcsA/AdK 三张卡）；`npm test` 483 项全部通过；数值对照基线 `docs/parity/numerical-baseline.json` 重新生成（仅 desktop 锁文件哈希变化，数值不变）。
2. **版本升到 0.6.0**：`desktop/package.json`/lock、README、desktop/README、skill 说明、docs 各处版本描述。
3. **自动发行工作流** `.github/workflows/desktop-release.yml`：推送 `desktop-v*` 标签 → 调用完整 `platform.yml` 闸门 → 全部通过后核对版本与源码提交 → 改名 EXE、附 Skill ZIP、证据 ZIP、`release-manifest.json`、`SHA256SUMS.txt` → 用 `docs/releases/<标签>.md` 作说明建 Release。`platform.yml` 增加 `workflow_call` 以便复用。
4. 发行说明 `docs/releases/desktop-v0.6.0.md`；`docs/RELEASE_VALIDATION.md` 增补自动发行与修复说明。
5. 分支 `claude/adoring-maxwell-yuvpoh` 合并进 `main` 并推送。
6. 会话环境的 git 代理不允许推送标签和删除远程分支，因此发布工作流增加 `workflow_dispatch`：在 main 上手动运行时由 GitHub 在闸门构建的同一提交上创建 `desktop-v0.6.0` 标签与 Release；并把 `platform.yml` 的并发组改为带调用方工作流名，避免与 main 推送触发的闸门互相取消。
7. 开发分支 `claude/adoring-maxwell-yuvpoh` 需在 GitHub 网页上手动删除（Branches 页面）。
