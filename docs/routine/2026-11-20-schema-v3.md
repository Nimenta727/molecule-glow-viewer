# 2026-11-20 — schemaVersion 3：作品配置与资源随场景保存

## 做了什么
- **schema**（`packages/schema`）：新增 v3 场景——`tools[]`（`{id, tool:{id,version}, config, state?}`）、`resources[]`（glow-resource 记录）必填；文件/外部资产可带 `resource:{id,version,sha256}`。校验引用：记录必须在场景内、哈希必须属于该资源版本、文件资产字节哈希与引用一致、工具条目 ID 与资源 id@version 不得重复。v2 的校验行为不变，v2 文档不得含 v3 字段；工程（`validateProject`）可同时容纳 v2 与 v3 场景。把 `SchemaValidationError` 拆到 `errors.mjs` 以避免循环引用。
- **升级**（`migrate.mjs`）：`upgradeSceneToV3`（只增不删；过渡期的 `provenance.resource` 提升为一等字段；字节缺失/哈希不符不阻止打开，只给诊断；已是 v3 则原样返回）、`attachStructureResources`（机制准备阶段新增的结构文件补记录和链接）。
- **工具条目**（`plugins/mechanism-catalog.mjs`）：`toolEntriesForScene`——声明了内置机制（旧 `process` 或 AdK 两态）的场景获得该播放器及**完整默认配置**的独立副本。
- **Viewer**：`work-scene.mjs`（载入边界升级、状态存取）、`resource-registry.mjs`（按场景内记录登记资源）、`mechanism-runtime.mjs`（把 `config` 和 `state` 传给播放器的 prepare/create）；导出的包携带 `tools` 与 `resources`；播放状态只存在工具条目里（旧场景仍回退到资产的 `provenance.playback`）。
- 文档：CONTRACT §4 加实现注记，§12 加进度与已知边界；ROADMAP 状态。

## 需要你知道的
- 兼容性：**旧版软件打不开 v3 文件**（已确认的取舍）。v2 文件仍可被新版打开并自动升级。
- 已保存的 `presentation.navigation` 优先于配置里的步骤/导航文字（作品保存后的呈现归场景所有），所以只改配置文字不会改变已保存过导航的作品。
- 默认表示：声明了 `core` 规则的场景（含官方 ATP 包）现在默认“功能分区”（上一步 AdK 工作中加入），重开导出包时可见。
- 授权未知的本地文件目前仍会随包嵌入；按 `embedAllowed` 过滤是后续项。
