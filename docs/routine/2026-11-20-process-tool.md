# 2026-11-20 — 4.4.4b 随机状态过程的工具与 Viewer 曲线面板

## 做了什么
- **工具** `org.glow.tool.stochastic-process`（`plugins/simulation/process-tool.mjs`，`layer-v1`，view + author），配置 `{process, schedule, seed, display}`：`process` 是马尔可夫声明，`schedule` 是参数时间表（每项一整组参数，缺的沿用前一项），`display` 是要画的行（计数、观测量、时钟、速率、从计数估算的电流）。校验器要求声明能运行、时间严格递增、参数在范围内、显示项引用真实存在的名字、大小 ≤ 200 KB。新添加时给一个两态通道模板，开箱即用。
- **Viewer 面板**（`apps/viewer-web/process-panel.mjs`）：播放/速度/从头开始/**跳到某一示意秒**/下载 CSV；每个声明的参数一个滑块——拖动就是**在此刻加一次参数变化并用同一种子重放**，所以过去不变、未来改变；各显示行的数值 + 增长的小曲线；离散状态；最近 8 条事件。动画总从种子重新开始，配置只存在作品的工具条目里。
- **Studio**：工具页由描述符生成字段——种子、起始参数、每次参数变化的时间与各参数，外加一个空位（填时间即新增一次变化，缺的参数沿用前一项）；越界被拒绝并给出中文原因。
- `observer.mjs` 增加 `readDisplay`（一行显示项在某一时刻的值）。

## 怎么验证的
- 单元测试 4 项（插件注册与停用释放、模板能跑且开放比例合理；配置校验——前一项的值被沿用、时间必须递增、参数越界、显示项引用不存在、种子负数回默认；读取各种显示项；Studio 式编辑含空位新增与越界拒绝）；全套测试通过；其余对照脚本（粒子 24/24、数据动画 6/6、动力学 5/5）仍一致。
- **浏览器实测**（预装 Chromium，软件渲染，页面无错误）：把 KcsA 的门控/渗透数据模型（5 条显示项、11 个参数滑块）放进作品，Viewer 打开后：面板出现且不与数据动画面板混淆；运行中数字增长；**跳到 60 s → 从头开始 → 再跳到 60 s，两次读数完全相同**（确定性）；在 t = 60 s 把电压滑块改到 −60 mV：此刻读数与改之前一样（过去不变），跳到 200 s 时与不改参数的运行不同（未来改变，估算电流 11.16 → 4.94 pA）；下载的 CSV 有表头和 201 行；**保存 → 关闭 → 重开：t = 60 s 的读数与最初相同**。Studio：导入这个作品，工具页列出种子/起始 pH、V 等和“第 1 次变化的时间”，把起始电压改成 −30、新增 45 s 的变化并把 pH 改成 7，导出的作品里时间表为 [0 s, V −30, pH 4.2] 和 [45 s, V −30, pH 7]（缺的沿用前一项）；把 pH 改成 99 被拒绝（“应在 3.5–8 之间”）；工具列表里能添加“随机状态过程”。

## 需要你知道的
- KcsA 的数据模型仍是测试目录里的**验收证据**，不是随产品发布的作品；KcsA 播放器仍用自己的链，改用数据模型和把它做成正式作品是 4.4.8。
- 曲线是各行独立缩放的小图，没有共用坐标轴；批量区室粒子与水合壳还没做；与经典“被动画阻塞的时钟”的显式比较仍待做。
- 没在真实 GPU/桌面版上验证；实测是软件渲染。
