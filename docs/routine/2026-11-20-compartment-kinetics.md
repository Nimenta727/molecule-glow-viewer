# 2026-11-20 — 4.4.3c 区室动力学（浓度 / pH / 膜电位）作为数据

## 做了什么
- 经典的“细胞区室模拟”模型是**写在各过程里的代码**（呼吸链、叶绿体、KcsA 各有一份 `cell: {init, step, controls, series, comps, dots, explain}`）。要让它们成为不带代码的数据作品，新增：
  - **安全表达式语言** `plugins/simulation/expression.mjs`：不用 `eval`；名字在读取时逐个检查，只能读到给定的数和固定的函数表（够不到 `constructor`、`__proto__`、`process`、`globalThis` 等）；长度和嵌套有上限；算术就是 JavaScript 的算术（`^` 是 `**`），所以从经典抄来的公式得到同样的位。
  - **动力学模型 v1** `kinetic-model.mjs`：常量、状态、开关/滑块、按顺序的 `let` / `set` 步骤、曲线与读数、各区室 pH（带颜色）、各区室自由分子数、讲解文字（`{表达式|位数}`）、只读输入（引擎的计数器）。运行规则与经典一致：预热 40×0.05 s，0.02 s 子步前向欧拉，每 0.25 s 一个曲线点；数值发散时停下并报告。
  - **接到数据动画上**：模型的粒子数让同名池（`名称@区室`）跟随浓度，`rate` 按经典夹在 0.5–1.8 改动画节奏，动画计数器作为模型输入；工具配置里可选的 `kinetics`（读取时校验：纯数据、≤200 KB、粒子写的区室必须存在）；Studio 可改常量与初值。
  - **Viewer 面板**：开关与滑块、读数 + 曲线、各区室 pH 色块、讲解文字。
- 顺手修了两处：不预热的模型在第一步前读数是 NaN（现在先算一次零时间步）；动力学首次给池填充的分子没计入引擎的初始库存，台账差了（现在计入）。

## 怎么验证的
- **与经典对照**（`tools/kinetics-parity.mjs`，报告 `docs/parity/kinetics-parity-report.txt`）：原样运行经典 `cell-kinetics.js`（`updateCellSim`、`drawCellHud`，只替换 DOM）和经典呼吸链、叶绿体的 `cell` 定义，同时运行把它们写成数据的模型（`test/models.mjs`），同一串 40 次开关变化，逐帧比较：状态变量、通量、池的目标数、pH 与颜色、读数、曲线、讲解文字。呼吸链、叶绿体各跑 60 s×16.7 ms 和 90 s×50 ms：**状态差恰为 0**，其余零分歧；pH 颜色 551 个值与经典 three.js 一致。**5/5 一致**。
- 单元测试：表达式（优先级、乘方、真值、三元、函数、与 JS 同位、各种错误和越权名字被拒）、动力学模型（编译错误指名道姓、运行、控件、保存恢复、发散停止）、引擎联动（计数器输入、池跟随浓度、`rate` 夹范围、台账仍平衡、确定性）、工具配置（校验、可编辑常量与越界拒绝）；全套 348+ 项通过；其余对照（粒子 24/24、数据动画 6/6）仍一致。
- **浏览器实测**（软件渲染，页面无错误）：把“K⁺ 外流使胞外浓度上升、E_K 变化”的模型放进 KcsA 数据作品：Viewer 里出现滑块和开关、三条读数曲线、两个区室的 pH、讲解；外流 9 次后胞外 K⁺ 5.0 → 10.4 mM，E_K −85.6 → −65.8 mV，讲解文字随状态切换；“从头开始”回到静息值，画面两次一致。Studio：工具页列出 `kinetics.constants.Ki0/Ko0`，改 `Ko0` 导出后生效，把 `Ki0` 改成 9999999 被拒绝（“应在 −1000000–1000000 之间”）。截图 `docs/images/data-animation-kinetics.png`。
