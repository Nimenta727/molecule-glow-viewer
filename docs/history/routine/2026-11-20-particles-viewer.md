# 2026-11-20 — 4.4.2c 粒子与流接进 Viewer

## 做了什么
- **`plugins/motion/solution.mjs`（纯逻辑）**：把池与流组成“可保存的一套”。池 = 某种分子 N 个在结构周围的溶液里扩散（不进蛋白）；流 = 两组残基之间的粒子流（路径用避开蛋白的布朗桥，三条略有不同）；时间尺度慢（逐个分子）/快（流显示通量；没有流时仍显示分子）；种子。**固定 1/30 秒一步**，同一种子同样步数画面相同，与帧率无关；长时间暂停后不会“快进”（每次最多 4 步）。`normalizeSolutionSpec` 清理保存/输入的配置（个数 ≤200、池 ≤8、流 ≤4、流速 0–3、表达式 ≤500 字符，坏项丢弃）。
- **视口 `setParticleCloud(tag, items, {overlay})`**：每组一个实例化球网格 + 带名字的标签（深色字，不会被物种颜色淹没）；`overlay` 让流画在蛋白之上（经典里“正在做事”的粒子在叠加层，通道里也看得见），池则像其他东西一样被蛋白挡住。重建场景/关闭时释放。
- **Viewer“溶液粒子”面板**（`apps/viewer-web/particle-flow.mjs`）：分子种类 + 个数 + 加入；流的起点/终点（选择语言写的残基组）+ 加入流；流速；时间尺度；播放/复位/全部移除；列表里可单个移除；说明文字给出每种分子的当前数量和错误原因（写错表达式会说明是哪条流的哪一端）。配置随作品保存（`viewerState.particles`），重开自动恢复。名字只用文本显示，没有把输入拼进 HTML。

## 怎么验证的
- 单元测试：`solution.test.mjs` 7 项（配置清理、同种子同画面且不进蛋白、固定步长与帧率无关、流与时间尺度、流错误解释且不影响其他流、增删、保存后重放）；全套 314 项通过；`check-feature-parity`、`check-docs`、`check-copies` 均通过。
- **浏览器实测**（预装 Chromium，软件渲染，页面无错误）：1K4C 加 K⁺×40、H⁺×25 → 画面出现紫色/黄色分子和名字标签，播放时画面在变、暂停后稳定；加流（chain A → chain C）并切到“快”，池隐藏、流画在蛋白之上；写错终点表达式得到中文说明且已有内容不受影响；**保存 → 关闭（面板清空）→ 重开：列表、时间尺度、说明文字全部恢复，视口与保存前逐像素相同**；“全部移除”后与未加粒子的原图逐像素相同。保存的 `.glow` 的场景文件里确有 `particles`。截图 `docs/images/particles-pool.png`、`particles-flow.png`。（逐像素比较只取视口区域，不含面板和时间条。）
