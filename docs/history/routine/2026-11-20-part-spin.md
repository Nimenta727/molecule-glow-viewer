# 2026-11-20 — 4.4.1d 部件旋转（对象动画）

## 做了什么
- **旋转的数学** `plugins/motion/rotation.mjs`（纯计算）：主轴分解（Jacobi，沿用经典的写法）；`chooseAxis` 的轴模式——**对称轴**（和另外两个特征值差得最多的那根，环绕它转）、**长轴**、**短轴**、**x / y / z**、**两组残基之间**（经典的 `axisFrom`：过第一组中心、指向第二组中心）；`rotateAbout`（绕过支点的轴转一个角）；`spinAngle`（转/秒 → 弧度，负数反向）。残基太少、两组中心重合、未知模式都给出中文提示。
- **视口**：把“节点的临时位移”扩成统一的“额外摆放”——位移（拆装用）和**旋转**（绕轴转一个角，连同朝向）叠加，节点原来的位姿被记住，清除即精确还原；机制播放器重置位姿时会把额外摆放重新放上去。
- **Viewer**：“部件旋转”面板——选轴模式（对称轴自动 / 长轴 / 短轴 / x / y / z / 两组残基之间，后者填两个选择表达式）、速度（-1 到 1 转/秒，负数反向）、播放、复位角度；部件列表里每个部件多一个“旋转”复选框。说明里写出轴的方向，并注明“旋转只是画面上的动作，不改变作品里的坐标”。表达式写错时给出中文报错且不改变画面。标记的部件、轴设置和当前角度随作品保存（`viewerState.spin`），重开自动恢复。与拆装、剖切可同时使用。

## 怎么验证的
- 单元测试 4 项：圆环/长杆的主轴、各轴模式、错误输入、绕轴转动（轴上的点不动、整圈回到原处、四分之一圈到预期位置、转速换算）。
- **与经典代码对照**（`tools/rotation-parity.mjs`，报告 `docs/parity/rotation-parity-report.txt`）：原样运行经典 `orientTransform`（长/短/对称轴三种模式）和 `spinPose`（绕支点转动的网格）：6ZPO、1K4C、4AKE 的各条链和 6ZPO 的整体共 42 根轴，方向差 ≤ 1e-15、中心差 ≤ 1e-13 Å；绕竖直支点转动 48 个点的最大差 1.5e-14 Å。**4/4 一致**。
- 浏览器实测（软件渲染，无页面错误）：6ZPO 标 3 个部件、对称轴、慢速播放：6 次取样得到 6 张不同的画面；暂停后画面不再变；“复位角度”后与未转时逐像素相同；两组残基的轴写错得到中文报错；保存→关闭→重开：3 个部件仍被标记、轴模式恢复、**画面与保存前逐像素相同**；取消全部标记后与原图逐像素相同。截图 `docs/images/part-spin.png`。（实测里发现 0.5 转/秒时取样会因整转同步而得到相同画面，是取样混叠，不是没转。）
- 验收清单新增 `structure.part-spin`（4.4.1，partial）及其经典/新版两条用例。

## 需要你知道的
- 经典里旋转速度可以**联动**模拟出来的通量（“转子速率”随质子账本变化）；通用版只有手动速度，联动留给机制/模拟那一层（ATP 合酶播放器已有自己的联动）。
- 轴只在内部计算，画面上不画出来；沿路径移动（离子沿孔道）属于 4.4.2 的粒子与路径，没在这里做。没在真实 GPU 上验证。
