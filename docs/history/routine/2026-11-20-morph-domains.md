# 2026-11-20 — 4.4.1c 构象变形的“叠合范围 + 结构域”配置

## 做了什么
- **按叠合范围拟合**：`fitStates(A, B, { core })`——`core` 是第一构象里的一组残基（例如刚性的结构域），只用它们里“两边都有”的残基做叠合，其余部分显示出自己相对叠合范围的运动，而不是把偏差摊到整条链上。返回里新增 `coreCount`、`rmsdCore`（叠合范围内的 RMSD）；叠合范围内少于 3 个匹配残基会明确拒绝。
- **结构域运动**：`domainMotions(拟合, 结构域, 进度)`——把插值状态的叠合范围重新对回第一构象的叠合范围，再量每个结构域的**转角（度）和质心位移（Å）**；残基太少的域不给数字。
- **Viewer 面板**：“叠合范围与结构域”折叠区——“叠合范围”（选择语言，空＝全部匹配残基）和“结构域”（每行 `名称: 选择表达式`），点“应用”后重新叠合、重画；信息行写出“在 146 个残基的叠合范围内 RMSD 1.98 Å …；结构域相对叠合范围的运动：NMP 转 44.8°、位移 9.8 Å；LID 转 52.2°、位移 14.4 Å”。表达式写错时给出中文报错，**什么都不改**。设置随作品保存（`viewerState.morph.config`），重开自动恢复；读回的设置会截断长度并只认字符串。

## 怎么验证的
- 单元测试 2 项新增（共 9 项）：构造的“一半刚性、另一半弯折 60°”：以刚性一半为叠合范围时叠合范围内 RMSD≈0，另一半转角 60°（进度 0.5 时 30°），全局叠合则做不到；叠合范围太小被拒绝；残基太少的域不给数字。
- **与 AdK 播放器的域测量对照**（`tools/domain-motion-parity.mjs`，报告 `docs/parity/domain-motion-parity-report.txt`）：AdK 的测量本身已和经典代码对照过。用 4AKE/1AKE 的 A 链，叠合范围 `chain A and resi 1-29,60-121,160-214`（CORE），NMP、LID 两个域，进度 1、0.5、0.25 的转角和位移与 AdK 播放器的 `measurements` **完全一致（差值为 0）**，7/7。
- 浏览器实测（软件渲染，无页面错误）：4AKE 加 1AKE；全局叠合 RMSD 18.45 Å；设置叠合范围与两个结构域后画面不同、信息行给出上面的数字（与 AdK 一致）；写错表达式得到中文报错且画面不变；保存→关闭→重开：叠合范围、结构域文字、进度、信息行都恢复，**画面与保存前逐像素相同**。截图 `docs/images/conformation-morph-domains.png`。

## 需要你知道的
- 叠合范围只选了 A 链时，B 链没有参与叠合，会离得很远（上面例子最大位移 62 Å）；想让二聚体的两条链一起叠合，把两条链的核心都写进叠合范围。
- 画面里的网格仍然是“跟随最近 4 个残基”的位移，不是“每个结构域整体刚性转动”；域的转角和位移是单独量出来的数字。
- 没做：两个以上的构象、真实路径动画、对象动画（旋转/沿路径移动）。没在真实 GPU 上验证。
