# 2026-11-20 — 4.4.0f 拆装的全原子界面

## 做了什么
- **全原子分类** `plugins/structure/full-interface.mjs`：两条链的每个原子互相比较，4 Å 内的接触分类——二硫键（CYS SG–SG ≤ 2.5 Å）、盐桥（Lys NZ / Arg NE NH1 NH2 对 Asp OD / Glu OE / 磷酸 OP，≤ 4.0 Å）、氢键（N/O–N/O 2.5–3.5 Å；已经是盐桥的原子对只算盐桥，不重复算氢键）、疏水接触（疏水残基侧链 C–C ≤ 4.0 Å）。N/O 距离 < 2.5 Å 的原子对不是化学键而是沉积模型的几何误差，单独报告“另 N 对过近，未计”。
- **直接读结构自己的原子**：经典版要从 RCSB 另外下载这条链的全部原子再对齐；新版的结构本来就带完整坐标（含组装副本），所以不需要联网，也没有“链太大”的限制。如果这条链只有 Cα/P 预览坐标（大型条目），会明确说“只有 Cα/P 预览坐标，没有侧链原子，需要完整结构才能判定化学键”，而不是给出空结果。
- **Viewer**：选中一条链后，“⚛ 计算全原子界面”按钮；每个伙伴下面列出各类化学键的数量（彩色小方块）、过近原子对、几个例子（如 `Glu99–Arg52 2.7 Å`）；3D 里用彩色细线连接真实的原子对（金＝二硫键、粉＝盐桥、蓝＝氢键、灰＝疏水，每个伙伴最多 25 条疏水线），拆开时线会被拉长。视口的 `setLinks` 现在支持“原子相对残基点的偏移”和每条线自己的颜色。

## 怎么验证的
- 单元测试 4 项（五类接触各一个构造用例、盐桥不重复计氢键、骨架原子不算疏水、Cα-only 链的明确提示）；全套测试、文档、验收清单、构建一致性检查见提交。
- **与经典代码差分对照**（`tools/full-interface-parity.mjs`，报告 `docs/parity/full-interface-parity-report.txt`）：把经典 `kitFullAtom` 的下载步骤换成从本地文件读同样的原子，两边分类同一批坐标；8 个真实结构里接触最多的 23 条链（共 100+ 个伙伴），每个伙伴的二硫键/盐桥/氢键/疏水接触（残基编号、原子名、距离到 1e-5 Å）和“过近”计数**全部一致，23/23**。
- 浏览器实测（软件渲染，无页面错误）：1K4C 选链 A → 计算 → 盐桥 2、氢键 15、二硫键 0、疏水 16（与离线对照的 33 个一致）；伙伴链 B：氢键 10、疏水 13、另 1 对过近；全部拆开后彩线被拉长连接各块。截图 `docs/images/take-apart-all-atom-interface.png`。

## 需要你知道的
- 分类规则与经典完全一致，所以它是**几何判据**，不是量子化学计算；没有氢原子参与，氢键只按重原子距离判断。
- 没做：Cα-only 预览条目的全原子界面（需要另外下载原子，以后再做）、经典的圆柱“界面带”（现在是细线）、按亚基种类上色、预设里的装配顺序关键字、命令 API。验收清单里这一项仍标 partial。
- 没在真实 GPU 上验证。
