# 2026-11-20 — 4.4.1a 通用构象变形（两个构象之间的插值）

## 做了什么
- **逻辑** `plugins/motion/state-pair.mjs`（纯数据与几何）：两个构象的残基按“链（含组装副本）+ label_seq”匹配；用**全部匹配残基**把构象 B 叠合到 A 上（沿用共用的 `superpose`）；每个匹配残基得到目标位置；B 的小分子用同一个变换搬到 A 的坐标系；统计匹配数、两边各自未匹配的残基数、叠合前后 RMSD、最大位移；自动往复的缓动（两端各停一下）；“哪个构象的小分子可见”（<0.4 看 A，>0.6 看 B，中间都不画）。少于 3 个匹配残基会明确拒绝。
- **显示的第二状态**：`conformationLayers` 给每一层几何一个“第二状态”——每个顶点跟随离它最近的 4 个匹配残基的位移（反距离加权，和 AdK/ATP/KcsA 播放器同一套办法）。为了能处理整条结构（几千个残基、几十万个顶点），在 `plugins/motion/conformation.mjs` 里新增了用网格加速的 `displaceVerticesGrid`，结果与原来的暴力版相同（测试里用随机数据逐位比较）。原有的三个播放器不受影响。
- **视口**：把“构象插值”从机制播放器里拆成通用的 `applyConformation`，新增 `setConformation(分数)`。
- **Viewer**：“构象变形”面板——输入第二个构象的 RCSB 编号（或选文件）→ 载入；进度滑块（第一构象 ↔ 第二构象）、“自动往复”、“移除第二构象”；信息行写出“匹配 428 个残基；叠合后 RMSD …（叠合前 …），最大位移 …”，并明说“画面是两个终点之间的线性插值（示意，不是真实路径）”。有自己构象播放器的作品（AdK、ATP、KcsA）不允许再叠加通用变形。

## 怎么验证的
- 单元测试 7 项（匹配键、拟合减小偏差、相同构象零位移、少于 3 个匹配被拒绝、B 的小分子随拟合移动、插值/缓动/往复/可见状态、网格版位移与暴力版一致、图层得到第二状态）。
- **与经典代码差分对照**（`tools/state-pair-parity.mjs`，报告 `docs/parity/state-pair-parity-report.txt`）：原样运行经典 `load-scene.js` 里的构象叠合那段，5 对真实结构（4AKE⇄1AKE、1K4C⇄5VK6、5VK6⇄5VKE、1K4C⇄5VKE、2HVK⇄2ITD）：匹配残基数、叠合后的目标位置（最大差 ~1e-13 Å）、B 的小分子随同一拟合移动，**15/15 一致**。
- 浏览器实测（软件渲染，无页面错误）：4AKE 加 1AKE、1K4C 加 5VK6：载入约 2 秒；**进度为 0 时画面与原图逐像素相同**；0.5 与 1 各不相同；回到 0 又与原图相同；“自动往复”时画面持续变化、滑块在 0–1 之间走动；**移除第二构象后与原图逐像素相同**。截图 `docs/images/conformation-morph-half.png`、`conformation-morph-end.png`。
- 验收清单新增 `structure.state-morph`（4.4.1，partial）及其经典/新版两条用例；数值基线因 `conformation.mjs`、`representation.mjs` 变动重新生成（三个播放器的数值对照仍通过）。

## 需要你知道的
- 经典版是对每个残基点直接线性插值；新版用“最近 4 个匹配残基的加权位移”移动每个顶点（图形网格不止是残基点），所以两个终点完全一致，中间画面是网格跟着残基走，细节不会逐像素相同。
- **没做**：B 构象的小分子不画（只在信息里计入）；第二构象不随作品保存（重开作品需要重新载入）；两个以上的构象；按结构域/轴/锚点配置的变形（AdK 播放器已有，通用版没有）；真实路径动画。画面里的选中标记在变形过程中不跟着动。
- 全局叠合对“结构域相对转动”的构象（如 AdK）会把偏差摊到整条链上，所以 RMSD 偏大；想看域运动应该用 AdK 播放器的 CORE 叠合。
