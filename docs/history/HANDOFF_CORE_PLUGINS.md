## 1. 三个确定的决定

1. **插件分两类**：
   - **纯数据**（光影包、场景、机理、分镜、会话）：社区可以随便上传，查看器只解释数据，不运行代码；
   - **功能插件**（科研、演示、格式互通、AI 接口……）：运行代码，但必须在沙箱里，只能通过受限接口操作主体；只有官方插件和维护者审核过的插件可以从工坊安装。
2. **白底墨线插画是主体自带的默认画风**；现在的发光团块和以后的其他画风都做成**光影包**。
3. **制作区 = 现在的开发者工作台（dev.html）的升级合并版**：既能可视化制作，也能让外部 AI 接入，还能在制作区里让 AI 直接代理制作。人和 AI 用同一个制作区、同一套命令。

## 3. 制作区（Studio）

制作区取代 `src/dev.html`，是一个独立页面（`web/studio.html`，桌面版菜单“制作区”），左边是工具，中间是实时查看器（同一个主体），右边是属性和 JSON。

### 3.1 功能区

| 区域 | 能做什么 |
|---|---|
| **导入模型** | 输入 PDB 编号 / 拖入 mmCIF、PDB / AlphaFold（UniProt 编号）；选组装体和链；多个结构组装（移动、旋转、对齐到参考结构、放到膜上）；自动定膜和手动调整 |
| **场景编辑** | 部件命名和配色、讲解（notes）、剖面、镜头书签、隐藏小分子、功能核心、证据补充、物种 / 代用说明；所有修改即时预览 |
| **动画编辑（时间轴）** | 可视化编排纯数据动画：画隔室、放物种池、在 3D 里点选锚点画粒子路径（flows）、设反应（reactions）和速率；时间轴上看事件；慢放 / 快放预览；种子 |
| **机理编辑** | 挂在当前场景上：选目标（配体 / 位点）、加步骤（状态、高亮选择、测量、反应式、证据、限制说明）、设干预；逐步预览；“在结构中查看”跳转 |
| **分镜**（演示插件启用时） | 把镜头 + 选择 + 表示 + 时间 / 步骤 + 说明存成幻灯片 |
| **JSON 视图** | 场景包源码，与可视化编辑双向同步；错误定位到字段路径 |
| **校验 / 预览 / 发布** | 校验（与 CI 同一套规则）→ 预览 → 导出 `.glow` → 投稿到工坊 |
| **历史** | 撤销 / 重做；每一步都是一条命令，进命令日志，可回放 |

### 3.2 AI 在制作区里的两种方式

1. **AI 接入**（外部 AI 操作制作区）：
   - 页面内：`window.glow` 命令接口 + 制作区扩展命令（`studio.*`）；
   - 嵌入：postMessage 桥（已有，写死白名单 + 用户允许）；
   - **MCP 服务器**（新增 `tools/glow-mcp/`）：让 Claude Code 等 AI 工具通过 MCP 驱动本地打开的制作区（桌面版内置，网页版通过本地桥接）；工具列表由 `help()` 自动生成。
2. **AI 代理制作**（在制作区里直接对话）：右侧“AI 助手”面板，由 AI 接口插件提供模型（见 5.4）。用户说“做一个血红蛋白结合氧气的机理，4 个血红素都要有”，AI 调用同一套命令逐步制作。
   - AI 的每次修改都是**提案**（显示差异），用户接受后才生效，可整体撤销；
   - AI 生成的内容在场景包里标记 `generatedBy: { ai: "<模型名>", reviewed: false }`，证据等级默认“建模 / 示意”，人工复核后才能改为更高等级；
   - AI 不能直接发布到工坊，发布必须人点。

## 4. 插件系统

### 4.1 插件种类

| 种类 | 是否运行代码 | 谁能发布 | 例子 |
|---|---|---|---|
| `style` 光影包 | 否（纯数据） | 任何人 | 发光团块、Goodsell 水彩、黑底科研、高对比度（色弱友好） |
| `content` 内容包 | 否 | 任何人 | 场景、机理、分镜、会话（就是场景包） |
| `feature` 功能插件 | 是（沙箱） | 官方 / 审核后 | 科研工具包、演示模式、格式互通 |
| `ai-provider` AI 接口 | 是（沙箱，可访问声明的网络域名） | 官方 / 审核后 | Claude、OpenAI 兼容接口、本地模型 |

### 4.2 插件清单 `glow-plugin.json`

```json
{
  "format": "glow-plugin", "version": 1,
  "id": "official.research-tools", "name": "科研工具包", "pluginVersion": "1.0.0",
  "kind": "feature", "author": { "name": "molecule-glow-viewer" }, "license": "Apache-2.0",
  "core": ">=2.0", "entry": "main.js",
  "permissions": ["read:structure", "read:selection", "write:selection", "ui:panel", "ui:command", "export:file"],
  "network": [],
  "contributes": { "panels": ["接触分析"], "commands": ["research.contacts", "research.rmsd"], "exporters": ["csv"] }
}
```

权限（最小集合，安装时逐项显示给用户）：

| 权限 | 含义 |
|---|---|
| `read:structure` / `read:scene` / `read:selection` | 读结构模型、场景、选择 |
| `write:selection` / `write:scene` | 改选择 / 改场景（会进命令日志，可撤销） |
| `ui:panel` / `ui:command` / `ui:menu` | 加面板、命令、菜单项 |
| `repr:add` | 注册新的表示（只能交几何数据，主体负责渲染和释放） |
| `sim:observe` / `sim:control` | 读模拟状态 / 播放暂停单步 |
| `export:file` / `import:file` | 让用户下载或选择文件（每次都经过用户操作） |
| `network:<域名>` | 只能访问清单里列出的域名 |
| `ai` | 调用 AI 接口插件 |
| `storage` | 插件自己的设置存储 |

### 4.3 运行方式

- 功能插件在**沙箱 iframe**（不同源、严格 CSP）或 **Worker** 里运行，只能通过消息调用主体的插件接口（= `window.glow` 命令 + 扩展点）；不能直接访问页面 DOM、Three.js 对象或用户文件。
- 扩展点：`registerPanel`、`registerCommand`、`registerExporter / Importer`、`registerRepresentation`（声明式几何）、`on(event)`（loaded / select / step / phase）。
- 生命周期：安装 → 权限确认 → 启用 → 场景切换时收到事件 → 停用 / 卸载（主体清理它注册的全部内容）。插件崩溃不影响主体（隔离 + 超时）。
- 版本：`core` 字段声明兼容的主体版本；不兼容时不加载并说明原因。
- 开发者模式：可以从本地文件夹加载未审核插件（醒目警告，不能分发）。

### 4.4 光影包 `glow-style`

纯数据，主体解释：

```json
{
  "format": "glow-style", "version": 1, "id": "official.glow-blobs", "name": "发光团块",
  "background": { "color": "#05070d", "gradient": null },
  "palette": { "entity": ["#ff5ca8", "#45d1ff", "..."], "nucleic": "#ffb347" },
  "material": { "kind": "glow", "roughness": 0.35, "emissive": 0.6, "rim": 0.8 },
  "post": { "bloom": { "strength": 0.9 }, "ao": true, "dof": false, "ink": false, "grade": { "saturation": 1.3, "contrast": 1.12, "vignette": 0.45 } },
  "labels": { "theme": "dark" }
}
```

- 材质和后处理只能从主体提供的**效果库**里选参数（不能上传着色器代码）。
- **可读性保护**：光影包不能隐藏标签、证据徽章、比例尺；主体检查标签与背景的对比度，不够时自动加描边。
- 主体默认画风“墨线插画”本身也用同一格式描述（`core.ink`），但打包在主体里、不可卸载。
- 现在的“背景模式 / 画质 / 简化样式”里与画风有关的选项迁移到光影包；画质（性能）选项留在主体。

### 4.5 工坊里的插件

- 工坊目录增加类型：`scene`、`mechanism`、`presentation`、`session`、`style`、`plugin`（索引按类型分文件）。
- 纯数据类型沿用现在的投稿机器人（issue → 自动校验 → PR）。
- 功能插件：投稿 = PR 到 `plugins/<id>/`；CI 检查清单、权限、体积、禁止的接口；**维护者人工审核代码后合并**；目录里记录每个版本文件的 SHA-256，主体安装时核对。
- 每个条目都有讨论帖（评分、评论），沿用现在的 `threads.mjs`。

## 5. 各插件的内容（原 WP8 / WP9 / AI 接口）

### 5.1 科研工具包 `official.research-tools`（原 WP8 分析部分）
二面角 / 角度测量、接触与氢键 / 盐桥表（排序、点击高亮、CSV）、两构象 RMSD 和逐残基位移图、界面面积（近似 SASA，标明方法）、AlphaFold（pLDDT 着色、PAE 图）、可重现会话（场景包 + 命令日志 + 种子 + 结构版本 + 推导参数）、自动生成方法说明和 BibTeX、模拟数据导出（计数、事件、曲线）。重计算放 Worker。

### 5.2 格式互通 `official.interop`（原 WP8 互通部分）
导出 mmCIF / PDB（当前选择）、ChimeraX `.cxc`、PyMOL `.pml`（复现结构、选择、颜色、视角）、MolViewSpec（Mol\*）+“在 Mol\* 中打开”、glTF / OBJ（3D 打印、Blender）；导入 ChimeraX / PyMOL 选择表达式的常用子集。

### 5.3 演示 `official.presentation`（原 WP9）
分镜（幻灯片 = 镜头 + 选择 + 表示 + 时间 / 步骤 + 说明）、演示模式（全屏、大字、翻页笔、演讲者备注、激光笔）、录屏（WebM，桌面版转 MP4）、高清截图、分享链接和嵌入代码；课堂同步以后接后端（WP10）。

### 5.4 AI 接口 `official.ai-claude`、`official.ai-openai-compatible`、`official.ai-local`
- 统一接口：`ai.chat(messages, tools)`；工具就是主体 + 制作区的命令（从 `help()` 生成）。
- 密钥由用户自己填，只存在本机（桌面版用系统凭据存储），**永远不写进场景包或工坊**。
- 网络权限只开放各自服务商的域名。
- 讲解用途（可选）：学生问“这个残基为什么重要”，AI 结合当前选择、来源和证据回答，回答标“AI 生成”。

### 5.5 Jupyter / Python `python/glow_viewer`（科研工具包的配套）
pip 包，在 notebook 里嵌入查看器，Python 调用命令并取回结果（测量、接触表、图片）。

## 7. 新工作包（详细）

> 大小：S 半天 · M 1–2 天 · L 3–5 天。目录归属见第 8 节。

**C6 机理运行时（主体，L，依赖 WP3 + WP4）**
`src/mechanism/`：`MechanismDefinition / Step / Evidence / Timeline / Intervention / ViewAdapter`（PLATFORM_ENGINEERING_SPEC §5.4）；步骤条、播放 / 暂停 / 单步 / 跳步、每步证据卡、测量、反应式、干预、事件日志和种子；第四个选项卡列出机理；场景里点位点 / 辅因子 / 机器 → “查看机理”，每步 → “在结构中查看”。官方模板：腺苷酸激酶、KcsA 过滤器、ATP 合酶催化口袋（做成工坊内容包）。
验收：三个模板从各自场景进入、逐步播放、每步回到结构；回归加机理场景（步骤数、每步高亮残基数）。

**C7 场景包 v2（主体，M，依赖 WP3）**
`src/pack/`：v2 字段（`compatibility`、`provenance`、`entryPoints`、`observables`、`controls`、`camera.bookmarks`、`selectionSets`、`representations`、`mechanism`、`presentation`、`session`、`style`、`generatedBy`），v1 自动迁移，错误带路径；预设从工坊目录生成（离线用打包的副本）。
验收：删掉硬编码预设后原预设全部从工坊打开且回归不变；v1 包全部迁移通过；SCHEMA.md 更新。

**P1 插件宿主（主体，L，依赖 WP2；与 C7 协调 `src/pack/`）**
`src/plugins/host/`：清单解析和校验、权限确认界面、沙箱 iframe / Worker、消息协议、扩展点、生命周期和清理、版本兼容、开发者模式本地加载、插件管理界面（启用 / 停用 / 卸载 / 权限查看）。
验收：一个示例插件（加一个面板 + 一个命令）安装、使用、卸载后资源计数回到原样；越权调用被拒绝；插件抛错或死循环不影响主体（超时终止）。

**P2 光影包（主体解释器 + 官方光影包，M，依赖 WP5）**
`src/style/`：`glow-style` 解释器、效果库、可读性保护；墨线插画作为 `core.ink`；把现在的发光风格做成 `official.glow-blobs`；再做一个高对比度（色弱友好）包。
验收：切换光影包不改变场景数据、证据和计数；回归在两种画风下都通过；对比度不足时自动加描边。

**H1 工坊扩展（M，依赖 C7、P1）**
`workshop/`、`.github/workflows/`：多类型目录、插件 PR 审核流程和 SHA-256、光影包和内容包投稿机器人、工坊界面按类型 / 层级 / 用途（教学 / 科研 / 演示）筛选、每个条目讨论帖。
验收：投一个光影包和一个机理包走通机器人；一个插件 PR 在 CI 里被检查；工坊里能安装插件并核对哈希。

**S1 制作区基础（L，依赖 WP3、C7）**
`src/studio/`（合并并取代 `src/dev.html`）：导入模型（PDB / 文件 / AlphaFold、组装、对齐、上膜）、场景编辑、JSON 双向同步、校验 / 预览 / 导出 / 投稿、撤销重做与历史。

验收：可视化做出现在官方 `kcsa-data` 和 `adk-reaction-data` 两个纯数据动画的等价物；做出一个新机理并通过校验。

**S3 AI 接入与代理（M–L，依赖 S1、P1、X4）**
`studio.*` 扩展命令、`tools/glow-mcp/` MCP 服务器、制作区 AI 助手面板（提案 → 差异 → 接受 / 撤销）、`generatedBy` 标记、AI 不能直接发布。
验收：用 Claude Code 通过 MCP 做出一个场景；在制作区里用一句话让 AI 做出血红蛋白结合 O₂ 的机理（4 个血红素），差异可逐条接受或撤销。

**X1 科研工具包 · X2 格式互通 · X3 演示 · X4 AI 接口 · X5 Python（插件，各 M–L）**

**D1 Windows 桌面优化（可选，S–M，依赖 WP1）**

## 10. 维护者验收清单（新增部分）

除 HANDOFF_PLAN 第 9 节的通用项外：
- [ ] **主体不依赖任何插件**：停用全部插件和光影包后，四个层级、制作区基础功能、回归全部正常。
- [ ] **插件隔离**：示例插件越权被拒；插件崩溃 / 死循环主体照常；卸载后资源计数回到原样。
- [ ] **光影包不改科学内容**：切换画风前后场景数据、证据、计数完全相同；标签和证据徽章始终可读。
- [ ] **制作区闭环**：不写 JSON 做出一个场景 → 校验 → 投稿 → 机器人开 PR。
- [ ] **AI 闭环**：MCP 或制作区 AI 面板做出机理；AI 修改可逐条撤销；内容标记 `generatedBy`；AI 不能直接发布；密钥不出现在任何导出物里。
- [ ] **工坊**：六种类型都能浏览 / 订阅 / 安装；插件哈希核对；纯数据投稿走机器人。
- [ ] **科研与演示插件**：按第 7 节各自的验收。
