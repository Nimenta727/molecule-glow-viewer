## 目标和边界

交付一个可使用的四模式浏览体验。用户从细胞进入局部系统，再进入蛋白质视图，并能从蛋白质或局部系统进入反应机理。每步都有明确的返回路径、相机定位、场景标题和当前选择。四种模式共享 Core 和 `.glow` v2 场景数据；模式是展示配置和导航状态，不是四套场景引擎。

本轮只使用通用几何体、颜色、标签和关键帧构造示例。蛋白质模式展示的是“单个复杂对象的查看方式”，示例必须标注为示意，不能暗示其形状来自实验结构。反应机理是过程展示模式，可以由局部系统或蛋白质进入，不强制作为空间尺度的第四层。

本轮不迁移 ATP 合酶、KcsA、翻译等科研过程，不建设插件商店，也不改动经典 Viewer 的科学内容。保留结构插件的现有可选入口和旧文件导入行为。

## 现有代码和约束

- `packages/core/` 提供场景文档、编辑事务、生命周期及时间线；`packages/schema/` 负责发布格式。模式数据须沿用现有契约，新增持久化字段前先更新 schema、转换与往返验证。
- `packages/render-three/viewport.mjs` 是新版共用的渲染适配器；相机过渡和对象拾取应在共用层提供能力，避免每种模式复制视口。
- `apps/viewer-web/` 是优先实现入口，已有示例场景、打开/保存、播放及结构插件开关。Studio 继续负责创作，Viewer 负责浏览。展示模式的作者配置若需要编辑，再以最小字段接入 Studio。
- `apps/studio-web/`、`packages/studio-editor/` 与 Viewer 使用同一 Core。经典 `src/` 和 `web/` 是兼容及回归参照。
- `desktop/scripts/package-platform.cjs` 将工作区打包为 Windows EXE。桌面发布前须确认新模式随现有打包入口进入产物。
- 现有设计原则及单位见 `PLATFORM_2_0_CORE_CONTRACT.md`、`PLATFORM_2_0_PACKAGE_AND_PLUGINS.md`。不得把示例的场景层级与实验原始坐标混写。

## 工作安排

按下列任务顺序提交。每项由实现 Agent 完成代码和自检，审查 Agent 检查边界、行为与回归，再开始下一项。每项均可单独回退。

### M0：冻结展示契约和示例

1. 检查当前 `main`、工作树和 0.4.0 基线。记录 Viewer/Studio 的普通窗口和窄窗口截图，以及通用场景的打开、播放、保存、重开结果。
2. 定义模式 ID `cell`、`system`、`protein`、`mechanism`，模式标题、入口节点、父级返回目标、初始镜头、可见标签和时间线关联。优先将导航关系写在场景内容中，不在 Core 中写死四个业务名称。
3. 用一个连贯的虚构示意场景做验收素材。细胞含可进入的区域，区域含局部系统，系统含可进入的对象，对象或系统关联两到三个机理步骤。稳定 ID 贯穿各视图；明确标注“示意场景”。
4. 写明场景中缺少目标节点、循环引用、无效镜头或无时间线时的行为。必要的 schema 扩展应版本化，并覆盖旧 `.glow` v2 文件的默认处理。

**验收**：示例文档能校验、保存、重开；无结构插件也能显示；旧 v2 示例和旧 v1 导入仍能打开。

### M1：共用导航与相机能力

1. 在 Viewer 增加当前模式、当前位置、进入路径和返回动作。场景切换与进入节点使用已有加载/资源生命周期，快速连续点击时只显示最后一次有效导航结果。
2. 在共用视口实现目标对象聚焦和镜头过渡；进入、返回、重置视角后选中对象与标签保持一致。减少动效设置下直接到达目标镜头。
3. 为键盘及按钮提供可达的返回操作和清晰焦点。场景关闭、文件替换和加载失败时清理导航状态，加载失败保留可用场景。

**验收**：四模式路径可进入、可逐级返回；反复进入退出后没有遗留动画帧、事件监听或几何体；窄窗口可操作。

### M2：四种展示界面

1. **细胞**：显示整体边界、区室或区域、方位信息与可进入热点。选中区域后显示名称和进入动作。
2. **局部系统**：突出多个对象的空间关系、方向和连接。对象可聚焦，并能进入单对象视图；不把通用连接误标成真实生化通量。
3. **蛋白质**：展示单对象的组成层级、可见部件、旋转与聚焦。基础示例为通用组合几何；保留以后由结构插件提供真实表示的接入点。
4. **反应机理**：展示步骤列表、参与对象、当前步骤、高亮和时间线同步。可从蛋白质或系统进入，返回原入口与原镜头；示例步骤均标为示意。
5. 四模式共用已有产品画风、底部播放状态和文件操作。模式专用面板只显示当前模式需要的信息，避免将四套控件同时堆在 Viewer。

**验收**：同一示例能走通全部入口，播放/暂停/拖动时间线后步骤和视口一致；打开没有模式元数据的普通场景时仍使用现有 Viewer 流程。

### M3：Studio 配置与交付复验

1. 让 Studio 能为现有场景节点设置进入目标、默认镜头和步骤关联。优先复用场景树、属性面板与现有关键帧编辑；只添加完整工作流确实需要的控件。
2. 在 Studio 保存工程、导出 `.glow` v2，随后在新版 Viewer 打开并完成四模式导航。重开工程后配置应保留；缺失目标要给可理解的提示。
3. 运行 Core、schema、Viewer/Studio、经典构建及副本一致性检查。核对普通与窄窗口截图，并检查打包的 Windows 入口。
4. 审查通过后提交到 `main`。若制作新的 EXE，使用新的版本与发布标签，保留 0.4.0 发布页及安装包。

**验收**：无需手改 JSON 即可在 Studio 制作和导出四模式示例，Viewer 打开后完整浏览；经典工作区原有基本操作通过回归。
