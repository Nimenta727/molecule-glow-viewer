# plugins/simulation — 数据反应与区室模拟

目标包 `plugins/simulation`（见 [CONTRACT_4.3.0](../../docs/CONTRACT_4.3.0.md) §3）的**第一步（4.4.3a，纯逻辑）**：经典 `src/sim/data-anim.js` 的“纯数据动画 v1”引擎。4.4.3b 起已注册为工具并接进 Viewer（见下）。

| 模块 | 内容 |
|---|---|
| `data-spec.mjs` | 读取 v1 声明：只保留已知字段、数值夹在范围内、数量设上限、**检查每一处引用**（池/流/反应写了不存在的区室，经典运行时直接崩，这里读取时就报错并说明）；锚点 `[x,y,z]` 或 `{ligand / ligands / residue / label_seq / part / membrane, offset}`；新增的可选 `conserved`（守恒量）。包里没有任何代码。 |
| `data-animation.mjs` | `DataAnimation`：区室（盒/外壳 + 侧面 + 膜 + 间隙）、池、**流**（取一个分子 → 布朗路径到入口 → 经锚点 → 出口 → 放进另一个区室，带事件与计数器）、**反应**（反应物到位点 → 保持 → 消耗 → 事件 → 计数 → 产物扩散到区室或淡出）、快时间尺度的粒子流。`step(dt)` 的顺序是经典一帧的顺序，所以同一种子取随机数的顺序也一致。 |

## 与经典的差别（有意的）
- **计量与守恒**（新增）：台账 `ledger`（每个物种创建/消耗/消失/取出/归还多少）+ 池边界的漂入/漂出计数，`balance()` 对每个物种给出“应有”和“实际”，两者相等才说明计量完整（官方两个包都平衡）；`conserved` 声明的量在每个反应完成时检查，不守恒就记入 `violations` 并出一个带 ⚠ 的事件（例：腺苷酸磷酸基团 ATP 3 + AMP 1 = 2 × ADP 2）。
- **读取即校验**：有错误的声明拒绝运行（经典会在运行中崩溃）。
- **事件在第一个点（`at: 0`）也会触发**：经典里长度为 0 的等待永远不会结束，这个事件从未出现过。
- **两点路径画成直线**（同 `plugins/motion`）：对照时经典用 0.01 Å 的两点路径做淡入淡出，three.js 会把它弄弯不到 0.001 Å，肉眼不可见。
- `orient.up`（整个结构绕水平轴转半圈）是**宿主**的事：引擎只提供 `flipAboutHorizontal`，宿主翻转结构后再创建引擎。
- 结构由宿主给出：`{ points, ligands: [{comp, centre}], residue(query), part(name), membraneY }`。

## 验证
`tools/data-anim-parity.mjs`：原样运行经典引擎（只替换渲染辅助），同一种子、同一结构（4AKE / 1K4C / 6ZPO 的真实残基位置），逐步比较池里的分子、在路上的分子、计数器、事件日志和快尺度的粒子流：**6/6 一致**（AdK 反应包 900 步、KcsA 数据包 1200 步，含并发的流与反应）。

## 4.4.3b：工具、取向适配器与 Viewer
| 模块 | 内容 |
|---|---|
| `structure-frame.mjs` | **取向适配器**：经典引擎跑在“结构轴竖直、以中心为原点”的模型上，“膜的上/下”就是 y 的大/小；新 Viewer 画的是原始坐标。适配器按包里的 `axis`（`plugins/motion/rotation.mjs` 的 `chooseAxis`，已与经典 `orientTransform` 对照）把残基和小分子转到竖直坐标系给引擎，按 `membranes: [{at, offset}]`（部件平均高度 + 偏移）放膜，按 `orient.up` 决定是否整体翻转；引擎的输出用 `toNative` 精确映射回原始坐标。 |
| `data-tool.mjs` / `index.mjs` | 工具 `org.glow.tool.data-animation`（`runtime: 'layer-v1'`，view + author）：配置 `{animation, axis, membranes, seed, scale}` 存在 `scene.tools[].config`；校验器要求声明能被引擎运行（每处错误指名道姓）；作者字段（种子/时间尺度/竖直轴/膜/每个池、流、反应的关键量）由描述符生成，Studio 工具页不需要专门代码。旧包里的 `animation` 在打开时自动变成工具条目（`mechanism-catalog.mjs` 的 `dataAnimationEntry`）。 |
| `apps/viewer-web/data-animation.mjs` | Viewer 面板：播放/从头开始/快慢/时间尺度、计数器、事件记录；用视口的粒子云（池 / 路上的分子 / 流）和事件标签（`setEventTags`）绘制。动画总是从种子重新开始，配置只在作品的工具条目里。 |

**限制**：只能编辑已有的池、流、反应的关键量，不能在 Studio 里新增；没有回放/干预；经典的“结合位点闪光”（`markHot`）没做；浓度/pH/膜电位见 4.4.3c。膜的位置用部件残基的平均高度近似（经典用该部件所有原子的平均高度）。

## 4.4.3c：区室动力学（浓度 / pH / 膜电位）作为数据
经典里“细胞区室模拟”的模型是**写在各过程里的代码**（呼吸链、叶绿体、KcsA 各一份 `cell: {init, step, controls, series, comps, dots, explain}`）。这里把它做成**无代码的数据模型**：

| 模块 | 内容 |
|---|---|
| `expression.mjs` | 安全的表达式语言（**不用 `eval`**）：数、名字、`+ - * / ^`（乘方，右结合）、比较、`&& || !`、`a ? b : c`、`exp log log10 sqrt abs min max pow floor ceil round clamp sign`。真值就是数（开着的开关是 1）。算术就是 JavaScript 的算术、按写的顺序，所以从经典代码抄来的公式得到同样的位。每个名字在读取时检查，够不到原型/全局对象；长度、嵌套深度有上限。 |
| `kinetic-model.mjs` | 模型格式 v1：`constants`、`state`（初值）、`controls`（开关/滑块）、`step`（按顺序的 `let` / `set`，`h` 是步长，后面的行看得到前面行的结果，和经典代码一样）、`series`（曲线与读数）、`compartments`（各区室的 pH → 颜色）、`dots`（各区室要显示多少自由分子）、`explain`（第一条条件成立的讲解，文字里写 `{表达式\|位数}`）、`inputs`（引擎的计数器作为只读输入）。`KineticSimulation`：预热 40×0.05 s、0.02 s 子步的前向欧拉、每 0.25 s 记一个曲线点、数值发散时停下并报告而不是画出来；`save()`/`restore()` 保存状态、开关和时钟。 |
| `data-animation.mjs` | 可选的 `kinetics`：模型的 `dots` 让名为 `名称@区室` 的池跟随浓度（和数据动画自己的同名池是同一个池）；`rate` 像经典那样（夹在 0.5–1.8）改变动画节奏；动画的计数器进入模型的 `inputs`。 |
| Viewer | “数据反应动画”面板里多出区室动力学区块：开关与滑块、读数 + 曲线、各区室 pH（带颜色）、讲解文字。 |

**验证**：`tools/kinetics-parity.mjs` 原样运行经典 `cell-kinetics.js`（`updateCellSim`、`drawCellHud`）和经典呼吸链、叶绿体的 `cell` 定义，同时运行把它们写成数据的模型（`test/models.mjs`），用同一串开关变化逐帧比较：状态、通量、池的目标数、pH 与颜色、读数、曲线、讲解文字——呼吸链和叶绿体各两种帧长共 5 项，**逐位一致（差为 0）**。这两个模型只是验收证据，真正的作品在 4.4.8。

**限制**：pH 体积（经典用着色器画整块溶液）还没画，现在是 pH 色块 + 数字；Studio 里只能改常量和初值，不能改模型结构；KcsA 的门控/渗透动力学是 4.4.4；回放/干预没做。

## 4.4.4a：随机状态过程（门控 / 渗透 / 阻断）作为数据
| 模块 | 内容 |
|---|---|
| `markov-model.mjs` | **数学模型**：通用的连续时间马尔可夫链引擎（精确的 Gillespie 采样，种子化随机流，参数时间表，时钟，计数器）。**作品配置**只是一份声明：`constants`、`parameters`（范围/步长/默认）、`variables`（离散状态，`gate_O` 在 gate 是 O 时为 1）、`derived`（共用公式）、`transitions`（按顺序；`when` 为真且 `rate` 为正才发生；`set` 改变量，`count` 计数）、`counters`、`clocks`（每段时间按 `add` 累加，可用 `dt`）、`observables`。速率公式用安全表达式语言。读取时逐处检查并给出中文错误；参数时间表要从 0 开始、逐段递增，每一组参数都按声明检查范围。 |
| `observer.mjs` | **观测**：`sampleRun` 把一次运行按步长采样成曲线（计数、时钟、观测量、离散变量；点数过多自动加大步长）；`ratesOf` 把计数变成速率；`currentFromCounts` 从计数的跨膜事件估算单通道电流（pA）；`toCSV` 输出表格。 |

**验证**：`test/kcsa-markov.mjs` 把 KcsA 的 pH 门控、TBA/Ba²⁺ 阻断、四态敲击渗透和 Na⁺ 排斥写成数据，与 `plugins/kcsa/kinetics.mjs` 在同一种子、同一参数时间表下比较：5 种时间表（默认、30 s 改 pH 与电压、野生型 + TBA 再 Ba²⁺、快时钟 + 高 Na⁺、无 Na⁺ 与对称 K⁺）× 24 个种子 × 10 个时间点，**事件序列、时间、状态、计数器、三个时钟逐位一致**（共约 1200 个状态、2000 多个事件）；与历史查询的划分无关，倒回得到同一答案。从计数估算的电流在三组电压/浓度下与解析稳态电流相符（96 个通道的系综，误差在统计范围内）。

**与经典的关系**：这里对照的是已提取的 KcsA 动力学（它与经典的差别——时钟不再被动画阻塞——已在 `plugins/kcsa/README.md` 说明）。**限制**：只有纯逻辑；还没注册为工具、没有 Viewer 的曲线面板、KcsA 播放器仍用自己的链；批量区室粒子与水合壳、与经典动画阻塞时钟的显式比较留到后续。排序语义有一处与经典不同且只在测度为零的情形：速率为 0 的转移不进候选表（经典里 Na⁺ 浓度为 0 时仍把零速率的 `na` 放在表尾）。

## 4.4.4b：随机状态过程的工具与 Viewer 曲线面板
| 模块 | 内容 |
|---|---|
| `process-tool.mjs` | 工具 `org.glow.tool.stochastic-process`（`runtime: 'layer-v1'`，view + author）。配置 `{process, schedule, seed, display}`：`process` 是马尔可夫声明；`schedule` 是参数时间表（每项一整组参数，缺的沿用前一项）；`display` 是要画的行（`counter` / `observable` / `clock` / `rate` / `current`）。校验器要求声明能运行、时间严格递增、参数在范围内、显示项引用真实存在的计数器/观测量/时钟。新添加时给一个两态通道模板，开箱即用。作者字段：种子、每次参数变化的时间与各参数，另有一个空位用来再加一次变化（Studio 工具页不需要专门代码）。 |
| `observer.mjs` `readDisplay` | 一行显示项在某一时刻的值（计数、观测量、时钟、速率、从计数估算的电流）。 |
| `apps/viewer-web/process-panel.mjs` | 播放/速度/从头开始/**跳到某一示意秒**/下载 CSV；每个声明的参数一个滑块——拖动就是在此刻加一次参数变化并用同一种子重放，所以过去不变、未来改变；读数 + 增长的曲线、离散状态、最近事件。动画总从种子重新开始，配置只在作品的工具条目里。 |

**限制**：KcsA 播放器仍用自己的链（尚未改用数据模型）；批量区室粒子与水合壳未做；曲线是各行独立缩放的小图，没有共用坐标轴。

## 4.4.5a：序列驱动的随机状态过程（以翻译为验证作品）
为了表达“状态空间随序列进展”的过程，马尔可夫引擎增加了四个能力（不影响已有的逐位一致）：
- **数值变量** `numbers`（带上下限的数，如 A 位密码子序号、肽链长度），转移里用 `inc` 增减、`assign` 赋值（表达式按事件发生前的状态求值）。
- **表** `tables`：作品自带的逐位置数据，公式里写 `codonClass(k)` 查表（查不到用默认值）。表通过 `$fn` 传给公式，表达式够不到别的东西。
- **分支** `outcomes`：转移被选中后再按权重抽一个分支，分支有自己的效果（哪种 tRNA 来了、药物是否锁住了因子）。
- **`ratesAt`**：给定状态和参数，返回“下一步可能发生什么”及速率（面板和对照测试都用它）。

**验证作品**：经典核糖体翻译的延伸/校对/终止/抗生素方案（`test/translation-model.mjs`，由氨基酸序列生成：每个位置的密码子类别、是否 Ala/Ser/Thr、近同源残基里 Ala/Ser/Thr 的比例，加 14 个状态、28 个转移）。`tools/translation-parity.mjs`：经典 `rates()` 在 4 万个随机状态上与数据模型**逐项相同**（相同的事件、相同的顺序、完全相同的速率），遗传密码、速率常数、抗生素常数、序列表也与经典一致。行为测试：延伸速率约 13 aa/s、读错率约 5e-4（巴龙霉素下约 1e-2，解析值与模拟值一致）、各抗生素的效应（四环素挡 A 位、氯霉素在 Ala/Ser/Thr 之后更强、红霉素堵通道并使 ErmCL 停滞、黄色霉素/夫西地酸锁住因子、没有 RF1 / EF-G / 三元复合物时停在哪一步）、确定性重放。

**限制**：这只是随机动力学部分；70S 结构动画、原子级特写、细胞角落与全细胞视图、翻译工具与 Viewer 面板还没做。与经典的差别：经典里分子时间被动画冻结，这里不会；`near-cognate` 的具体氨基酸不记录（只记是否 Ala/Ser/Thr，用于氯霉素背景）。
